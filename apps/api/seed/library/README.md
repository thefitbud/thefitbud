# FitBud library seed

Provenance:
- Foods: bundle `fitbud-library-v2`, release **2026.10.9** (1,243 foods).
- Exercises: base **2026.10.21-v3** (1,362 exercises).

Both are copied from `incoming/`, which is read-only input. The generation pipelines live outside this repo; these files are the loadable output only.

## Contents

- `sql/01_lookups.sql` … `sql/06_seed_version.sql`: the locked release. They are byte copies of `incoming/2026.10.9/sql/`, with one `sha256` per file in `manifest.json`.
- `sql/02b_food_extras.sql`: food extras that load after 02. It holds comments only for now and is not in the manifest.
- `sql/03b_exercise_base.sql`: the exercise base. It is generated by `pnpm exec tsx scripts/emit-exercise-base.ts` from `incoming/exercise-base-2026.10.21-v3/`; do not edit it by hand. It replaces the 353 exercises of `03` (same ids and slugs) and adds the rest. Media keys are `exercises/<slug>/<n>.<ext>`.
- `sql/08_post_seed.sql`: post-seed corrections to the locked release (I2f). It is not in the manifest.
- `00_wipe_legacy_dev.sql`, `07_post_wipe_dev.sql`: local dev only. They rewrite legacy rows from early migrations.
- `library-2026.10.9.json`: canonical JSON export for review and tooling.
- `ATTRIBUTION.md`: in-app attribution text for the foods release. Per-image credits for the exercise drawings are in `exercise_library_media` and `incoming/exercise-base-2026.10.21-v3/MEDIA_ATTRIBUTION.md`.

## Load

Local, from the repo root (`pnpm db:reset` runs it too):

```bash
pnpm db:seed:library
```

The local order is `00`, `01`, `02`, `02b`, `03`, `03b`, `04`, `05`, `06`, `07`, `08`, then `05` again to rebuild FTS. A file with comments only is skipped, because wrangler rejects it. A file over 5 MB is split between statements into chunks (`scripts/lib/sql-chunk.ts`): `02_foods.sql` (~23 MB) and `03b_exercise_base.sql` (~13 MB).

Staging or production (Firoz only; agents never run remote):

```bash
cd apps/api
pnpm exec tsx scripts/library-seed.ts --remote --env staging --yes --print   # list the commands, run nothing
pnpm exec tsx scripts/library-seed.ts --remote --env staging --yes           # load fitbud-staging
```

Remote mode skips `00` and `07`. It needs `--env staging|production` and `--yes`; any other argument is refused.

**Note:** `wrangler d1 export` cannot export FTS virtual tables. Drop or exclude `food_search_fts` / `exercise_search_fts` before export and re-run `05_search.sql` after import.
