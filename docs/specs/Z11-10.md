## Outcome
A change under `apps/mobile/src` that breaks the zone guard fails CI instead of being served a cached pass.

## Context
- From the W10 report: `packages/core/src/zone-guard.test.ts` scans `apps/mobile/src` (l.37, l.188), but `@fitbud/core#test` does not hash those files, so CI served a cached pass and hid two red-main failures in W10.
- Recommended fix (D-W11-F4): a package-specific task in `turbo.json`, `"@fitbud/core#test"`, with `dependsOn: ["^build"]` and `inputs: ["$TURBO_DEFAULT$", "$TURBO_ROOT$/apps/mobile/src/**"]` (turbo ^2.5 supports both). Moving the guard into `apps/mobile` is the fallback only if the root-relative input does not work; it would need `files_owned` changes, so stop and report instead.
- `package.json` manifests are owned by Z11-7; this task changes none.
