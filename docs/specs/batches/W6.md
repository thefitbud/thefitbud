## Decisions
- **D-W6-1 One migration lane:** Z6-1 → Z6-2 → Z6-3 → Z6-4, each taking the next free number (0035–0038 expected after Z5-1's 0034), so two branches never claim one number. Decided by the planner.
- **D-W6-2 Module ownership:** each API lane owns its own route, domain, contract and client-augment files (stubs from Z5-4) and its own `<module>.authz.test.ts`; nobody edits the shared index files or `authorization-matrix.test.ts` in W6. Decided by the planner.
- **D-W6-3 Load on save** is its own task (Z6-15) in the logging lane, because `workouts.ts` and `compliance-logging.ts` are owned by the EC1 tasks in this batch. Decided by the planner.
- **D-W6-4 SPB does not wait for DS2:** D11 locks the API scope; DS2 frames are needed for the W7 UI only. Decided by the planner.
- **D-W6-5 Payments are tracking only** (resolved 30 Oct): no collection, gateway, invoice or session counting fields, enforced by schema. Carried over.
- **D-W6-6 EC1f dropped:** EC1a (merged 30 Oct) stamps `resolved_at` when ending coaching (`relationship-lifecycle.ts:102-115`), and staging (2 Nov) and production (W4) were created after it, so no NULL rows can exist. Firoz's P2 step confirms with a read-only count. Decided by the planner.
- **D-W6-7 Account deletion = archive, then purge (was Q-W6-2):** deleting an account archives it for 6 months; during that time the user can reactivate it by signing in again; after 6 months it is purged. Permanent deletion straight away is by emailing tech@thefitbud.com, which support handles with a runbook. A trainer with active clients must end them first. Firoz, 3 Nov (6 months, reactivation, email); the trainer rule was the recommended default and is kept by FitBud UI.
- **D-W6-8 How archive, reactivation and immediate deletion work:** new migration Z6-16 adds `archived` to `users.account_state` with `archived_at` and `purge_after`; reactivation is sign-in plus one confirm (`POST /account/reactivation`); relationships ended by the deletion stay ended; immediate deletion sets `purge_after` to now with one remote D1 statement from `docs/runbooks/account-deletion.md`, so there is no admin endpoint and no new secret. Decided by FitBud UI, 3 Nov.
- **D-W6-9 Backup token scope (was Q-W6-1):** option (a), a backup Worker. Secret `CF_D1_EXPORT_TOKEN`, one account-owned API token per env with only **Account · D1 · Edit** on the FitBud account (the D1 export endpoint is a write call; Cloudflare has no export-only or per-database D1 permission), no other permissions; R2 is written through the bucket binding, so no R2 token. FitBud UI creates and sets it after merge. Decided by FitBud UI, 3 Nov.
- **Carried over (decided):** D2 (form v2, option A), D11, D12/D12b, EC1 rules (locked 23 Oct).
