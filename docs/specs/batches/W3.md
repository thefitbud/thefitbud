## Conflicts between v14, the code and CLAUDE.md (listed, not resolved)
1. v14 C3/X4b says device-token registration returns 403 for trainees; the route allows both roles (`apps/api/src/routes/notifications.ts:134`, `:141`); the 403 is `FORBIDDEN_ROLE` with no selected role (`apps/api/src/middleware/auth.ts:94`), and the mobile app skips trainees by choice (`apps/mobile/src/auth/AuthProvider.tsx:149-150`).
2. Widget outbox writes `workout.log_set` (`apps/mobile/targets/FitBudLiveActivity/FitBudLiveActivity.swift:16`); the sync contract has `workout.complete_set` (`packages/contracts/src/sync.ts:41`) (D-W3-5).
3. v14 X4c "trainee and trainer notification types": trainer events are stored as delivered without a push (`apps/api/src/domain/inbox-notify.ts:41`) (D-W3-1).
4. The Android scaffold says "There is no rest timer" (`apps/mobile/targets/android/WorkoutSetNotification.kt:15`) while D-W2-12 put the rest timer in the beta for iOS (D-W3-3).
5. A re-registered token for the same installation fails on the unique index (`apps/api/drizzle/0010_notifications.sql:16`) because the route looks up by token only (`apps/api/src/routes/notifications.ts:157`). Fixed by X4b.
6. Sizing/model: v14 X4b (push-mobile + push-api) and BT3 (web + mobile) mix layers → split into X4b/X4e and BT3/BT3b; v14 LA3 (S) is native + JS → LA3 (M) and LA3b (S); v14 X4c model "plan" vs the S → sonnet rule.
7. `Agents.md` ranks wiki pages above the spec; CLAUDE.md says the spec and CLAUDE.md win (D-W2-10, task DC1).
8. The widget App Group is hard-coded (`FitBudLiveActivity.swift:9`); X6 (W1) makes it per variant. LA2 must read the same per-variant group.
