- **D-W3-8 Push delivery is at-most-once.** Decided by Firoz, 31 Oct 2026. When the provider has accepted a push but the write recording that acceptance fails, the queue retry must **not** send again: mark the attempt before calling the provider, and on a retry whose outcome is unknown record it as uncertain instead of resending. Chosen over at-least-once, so a trainee is never sent the same reminder twice; the cost is that a reminder can rarely be lost. Matches "dedupe before delivery" and "record provider acceptance separately from completion" in AGENTS.md. Why it is needed: on `main` today `deliverReminderMessage` skips a redelivery only when `providerStatus` is already `accepted`, which is exactly the write that failed, so the queue's `message.retry()` sends the push a second time (confirmed in the pre-W3 check, 31 Oct, and recorded as a W2 follow-up). The fix needs an attempt marker written before the provider call, so it carries a migration and cannot ride along in a copy or UI PR. Whichever push-api spec takes it (X4c or a new id) owns `apps/api/src/domain/reminders.ts`, `apps/api/src/jobs/reminders.ts` and that migration. **Task:** X4i (M, opus, reminders lane: X4c → X4i → X4f → X4h), decided by Firoz, 1 Nov 2026.
- **D-W3-5 Live Activity outbox operation. Decided by Firoz, 1 Nov 2026: (a)**, LA2 maps `workout.log_set` to `workout.complete_set`; no API change.

## Conflicts between v14, the code and CLAUDE.md (listed, not resolved)
1. v14 C3/X4b says device-token registration returns 403 for trainees; the route allows both roles (`apps/api/src/routes/notifications.ts:135`, `:141`); the 403 is `FORBIDDEN_ROLE` with no selected role (`apps/api/src/middleware/auth.ts:96`), and the mobile app skips trainees by choice (`apps/mobile/src/auth/AuthProvider.tsx:191-192`).
2. Widget outbox writes `workout.log_set` (`apps/mobile/targets/FitBudLiveActivity/FitBudLiveActivity.swift:16`); the sync contract has `workout.complete_set` (`packages/contracts/src/sync.ts:41`) (D-W3-5).
3. v14 X4c "trainee and trainer notification types": trainer events are stored as delivered without a push (`apps/api/src/domain/inbox-notify.ts:41`) (D-W3-1).
4. The Android scaffold says "There is no rest timer" (`apps/mobile/targets/android/WorkoutSetNotification.kt:15`) while D-W2-12 put the rest timer in the beta for iOS (D-W3-3).
5. A re-registered token for the same installation fails on the unique index (`apps/api/drizzle/0010_notifications.sql:16`) because the route looks up by token only (`apps/api/src/routes/notifications.ts:158`). Fixed by X4b.
6. Sizing/model: v14 X4b (push-mobile + push-api) and BT3 (web + mobile) mix layers → split into X4b/X4e and BT3/BT3b; v14 LA3 (S) is native + JS → LA3 (M) and LA3b (S); v14 X4c model "plan" vs the S → sonnet rule.
7. `Agents.md` ranked wiki pages above the spec (D-W2-10). On `main` it is now `AGENTS.md` (DOC1), which puts the spec first (`AGENTS.md:19`); DC1 confirms and closes.
8. The widget App Group is now per variant (`FitBudLiveActivity.swift:10` reads `FitBudAppGroup` from Info.plist, X6). LA2 must read the same per-variant group. Resolved on `main`.
