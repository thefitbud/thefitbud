- **D-W4-12 BT6 added: fix the api-client WebSocket handshake flake. Decided by Firoz, 4 Nov 2026**, handed over from W3b as D-W3b-28.
  `packages/api-client/src/index.test.ts:567`, "never calls the refresh hook when the handshake fails", waits a fixed `setTimeout(10)` for a fake WebSocket's error/close to be emitted, then reads the spies — so a loaded runner reads them before they are called. *"Replace the fixed 10 ms timer with an awaited event or condition."* Await the callback (or a condition on it), not a longer timer: raising the delay hides the race instead of removing it, and a timer-based test on a loaded runner has no safe constant.
  **Evidence it is intermittent, not broken:** two failures in unrelated W3b PRs — CU13 (#207, first `ci` attempt; passed on a re-run of the identical SHA with nothing changed) and CU22's post-merge full run (passed 3/3 on re-run). Neither touches `packages/api-client`. It costs `ci` re-runs, which matters in a batch that ends in store submission.
  **Scope:** `packages/api-client/src/index.test.ts` only, and only the timing mechanism — the assertions stay. **Do not** weaken or delete the assertion to stop the flake (AGENTS.md: never weaken tests to make a change pass); the test must still go red if the refresh hook is called on a failed handshake. Mutation-check that. Lane `api-client`, model sonnet, size S, no spec file — this decision is the brief.
