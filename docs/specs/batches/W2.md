## Decisions
- **D-W2-1 Email provider: ZeptoMail** (India region API, `POST https://api.zeptomail.in/v1.1/email`, header `Authorization: Zoho-enczapikey <token>`, secret `ZEPTOMAIL_TOKEN` set by Firoz). Chosen over Resend and SES. Decided by Firoz, 30 Oct (v14 D-B3).
- **D-W2-2 Web hosting:** a web Worker `fitbud-web-<env>` serves the SPA with fallback to `index.html` and forwards `/api/*` to the API Worker through a service binding, stripping `/api` like the Vite proxy; same origin, no CORS, first-party cookies. Web on `app-staging.thefitbud.com` / `app.thefitbud.com`, API also on `api-staging.thefitbud.com` / `api.thefitbud.com`. Chosen over adding CORS. Decided by Firoz, 31 Oct (v14 D-B10).
- **D-W2-3 Client token refresh:** clients store `refreshToken` the same way each stores its token today, refresh before `expiresIn` and once on a 401 then retry once, sign out on refresh failure. Decided by Claude's recommendation adopted 31 Oct (v14 D-B6, AU1c).
- **D-W2-4 Logs:** staging observability at 100%, production `head_sampling_rate = 0.2`. Decided in v14 OB1 (Claude, 31 Oct).
- **D-W2-5 Live Activity scope, if it is in the beta:** local updates only (no APNs), cut-line Thu 12 Nov. Decided by Firoz, 31 Oct (v14 D-B7, C13). Whether it is in the beta at all is D-W2-6.

- **D-W2-11 Invite links `/i/<token>` on the web host. Open (new, from code reading).** `apps/api/src/lib/public-app-url.ts:17-22` builds `https://<APP_HOST>/i/<token>`, and APP_HOST is the web host, but `/i/*` is an API route (`apps/api/src/routes/invite-landing.ts:26`, `apps/api/src/index.ts:90`). Through the web Worker it would hit the SPA fallback. Options: (a) the web Worker also forwards `/i/*` to the API without stripping the prefix; (b) invite links use the API host (new `API_HOST` var plus a change in `public-app-url.ts`). Recommended: (a) (no API change, links keep the app domain). Blocks: WD1.
- **D-W2-12 Rest timer in the Live Activity. Open (new).** Frame `27c-trainee-lock-live-rest-ios.png` shows a rest state on the lock screen; v14 and `apps/mobile/plugins/withLiveActivity.js:10` say there is no rest timer. Options: (a) no rest in the activity for the beta, 27c is post-beta; (b) add a rest countdown (new task, LA1c). Recommended: (a). Blocks: nothing in W2 if (a); LA1c if (b).
- **D-W2-13 Persist the refresh token on native. Open (new).** On native the access token lives in memory only (`apps/mobile/src/lib/sessionStorage.ts`), so users sign in after every app restart. D-W2-3 says store the refresh token "the same way". Options: (a) keep memory only for the beta; (b) persist both tokens in secure storage (new dependency, new task AU1f). Recommended: (a) for W2, revisit before store builds. Blocks: AU1d only if (b) is chosen before it starts.
- **D-W2-14 Invitation accept token exchange: new task AU1e or fold into AU1b. Open (new).** `apps/api/src/routes/invitations.ts:721-735` returns `mintAuthToken` output, which AU1b's gap list does not cover; in Firebase mode a new trainee would land signed out. Options: (a) new W2 task AU1e (spec written); (b) add the gap to W1's AU1b if it hasn't started. Recommended: (a) (W1 specs are merged; no reopening). Blocks: AU1e, AU1d.
- **D-W2-15 Lane names vs the spec template. Open (carried from W1).** `docs/specs/_TEMPLATE.md` lists `api | api-perf | infra | seed | web | mobile | ops`; W1 and W2 use batch-specific lanes (`client-auth`, `auth-api`, `email`, `api-ops`, `mobile-native`). Options: (a) widen the template comment to "any lane named in the batch file"; (b) rename lanes to the template list. Recommended: (a). Blocks: nothing (QA notes it).
