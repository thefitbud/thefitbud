## Decisions
- **D-W2-1 Email provider: ZeptoMail** (India region API `api.zeptomail.in`, `POST https://api.zeptomail.in/v1.1/email`, header `Authorization: Zoho-enczapikey <token>`, secret `ZEPTOMAIL_TOKEN` set by Firoz). Chosen over Resend and SES. Decided by Firoz, 30 Oct (v14 D-B3).
- **D-W2-2 Web hosting:** a web Worker `fitbud-web-<env>` serves the SPA with fallback to `index.html` and forwards `/api/*` to the API Worker through a service binding, stripping `/api` like the Vite proxy; same origin, no CORS, first-party cookies. Web on `app-staging.thefitbud.com` / `app.thefitbud.com`, API also on `api-staging.thefitbud.com` / `api.thefitbud.com`. Chosen over adding CORS. Decided by Firoz, 31 Oct (v14 D-B10).
- **D-W2-3 Client token refresh:** clients store `refreshToken` the same way each stores its token today, refresh before `expiresIn` and once on a 401 then retry once, sign out on refresh failure. Decided by Claude's recommendation adopted 31 Oct (v14 D-B6, AU1c).
- **D-W2-4 Logs:** staging observability at 100%, production `head_sampling_rate = 0.2`. Decided in v14 OB1 (Claude, 31 Oct).
- **D-W2-5 Live Activity in the beta, local updates only, cut-line Thu 12 Nov.** Decided by Firoz, 31 Oct (v14 D-B7, C13).
- **D-W2-6 Live Activity beta status. Open.** v14 contradicts itself: §4 line "Post-beta: … Live Activity (C3)" vs D-B7 / C13 "Live Activity is in the beta". Options: (a) in the beta per D-B7 (newer, explicit Firoz answer); (b) post-beta. Recommended: (a). Waits on it: LA1 (and LA2, LA3 in W3).
- **D-W2-7 Trainer-web URL in the mobile app. Open.** `apps/mobile/src/trainer/MoreScreen.tsx:13` defaults to `https://coach.thefitbud.com`; D-B10 puts trainer web on `app.thefitbud.com`. Options: (a) WD1 or a small mobile task switches the default to `https://app.thefitbud.com` and sets `EXPO_PUBLIC_TRAINER_WEB_URL` per EAS profile; (b) also serve `coach.thefitbud.com`. Recommended: (a), as a separate mobile spec (backend and UI never share a spec). Waits on it: WD1.
- **D-W2-8 `MEDIA_PREFIX` in the `Env` type.** I4b (W1) typed it structurally to avoid the auth lane's `types.ts`. Recommended: OB2 or I5 adds `MEDIA_PREFIX?: string` to `Env` (whichever spec owns `types.ts` in W2). Open until the W2 specs assign `types.ts`.
- **D-W2-9 Is the I6 deploy blocked by AU2's guard?** AU2 refuses `PUSH_PROVIDER_MODE=test` outside local, and `expo` mode arrives only with X4a (W3), but I6 is in W2→W3. **Open.** Options: (a) I6 waits for X4a; (b) I4a's staging `PUSH_PROVIDER_MODE` stays `expo` and X4a is pulled into W2; (c) allow a `disabled` push mode for staging until X4a. Recommended: (b). Waits on it: I6 (Firoz), X4a scheduling.
