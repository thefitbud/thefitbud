## Outcome
Opening the Workout tab focuses today's date in the week strip, not Saturday. The screen shows one "Workout" title, as in frame 10.

## Context
- From the W9 report follow-ups (Z9-6 review) and Firoz's W9b brief, 11 Nov 2026.
- `WorkoutTab.tsx` ~l.256–264 computes `lowerBodySaturday = addDays(startOfWeekMonday(today), 5)` and uses it as the default `focusDate` whenever `selectedDate` is today or unset. Use `pickedDate ?? selectedDate ?? today`, and drop `lowerBodySaturday` if nothing else reads it.
- `WorkoutTab.week.test.tsx` pins the Saturday default ("The tab opens on the Saturday of the current week"). Rewrite it to pin today. Add a test where today is a Wednesday and the tab opens with Wednesday focused.
- `TraineeShell.tsx` renders `AppTopBar` with `TAB_TITLES.workout` ("Workout") above WorkoutTab, which also renders its own "Workout" page title (~l.774). Diet avoids the duplicate by not rendering `AppTopBar` for its tab (`tab !== "diet" && tab !== "more"`, ~l.931), and instead gets `unreadNotifications` from the shell (~l.980–987) and draws its own `Bell` in its title row (DietTab.tsx ~l.11, ~l.678). Do the same for `workout`: skip `AppTopBar` on the workout tab, pass `unreadNotifications` to `<WorkoutTab>` (~l.966–977), and render a bell in WorkoutTab's title row that opens the notifications overlay through `onOpenOverlay({ screen: "notifications" })`, as frame 10 shows. The sync entry goes, as on Diet. If anything beyond the bell and the sync entry would be lost, stop and report.
- Re-check against the latest `main` before building (AGENTS.md).
- Design review: Z11-1 is not on `main`, so the reviewer compares captures with frame 10 side by side.
