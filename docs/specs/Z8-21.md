## Outcome
A set load label whose digits are separated by any run of whitespace (for example `4         0 kg`) is read as text, never as one number. Today a run of 9 or more spaces is joined into one number (`40`).

## Context
- Added 10 Nov 2026 from the W7 report "For Firoz" item; Firoz decided it (planner brief, 10 Nov 2026): digits separated by whitespace must never be joined into one number.
- `apps/api/src/domain/load-parser.ts` (~l.122–126) collapses spaces with three passes of `"  " → " "`, then rejects `/[0-9.] [0-9.]/`, then drops all spaces. A run of 9+ spaces survives the collapse as 2+ spaces, so the single-space check misses it and the digits are joined.
- Z7-28 pinned that behaviour in `load-parser.test.ts` ("joins digits separated by 9 or more spaces into one number") and said a change needs a decision; this is that decision.
- Migration `0035_numeric_set_load.sql` did the same collapse in SQL for its one-off backfill. It is applied: **never edit it**. This task changes only the runtime parser; rows already backfilled stay as they are (no data rewrite). Say so in the PR.

## Gap list
- `load-parser.ts`: reject digits (or a decimal point and a digit) separated by **one or more** whitespace characters, through the existing `TEXT` return; keep the space-collapsing for words and units (`40         kg` → 40 kg, `BW + 10 kg` → bodyweight plus 10) unchanged.
- `load-parser.test.ts`: the test "applies the 9-space join to both labels while the kind follows the actual label" (~l.241) also pins the join; update it so the wide prescribed label is text (`prescribedLoadKg: null`, `actualLoadKg: null`, `loadKind: "bodyweight"`).
- `load-parser.test.ts`: replace the Z7-28 "joins digits … 9 or more spaces" pin with a test that every gap length (1–40 spaces, and tabs) between digits returns text; keep the "run of spaces around words and units" pin.
- Written against `main` at 0eae53c; re-check against latest `main` (AGENTS.md).
