## Outcome
A returning visit to the trainer web does not re-download or revalidate its hashed JavaScript and CSS. The browser keeps those files for a year. `index.html` (and other HTML) is always revalidated, so a new deploy is visible on the next visit. Bundle splitting is not part of this task.

## Context
- FitBud Tech's performance audit of 25 Nov 2026 (after the W14 database-latency fixes) found that the trainer web's hashed assets (about 406 KB of JS/CSS) are served with Cloudflare Workers' default `Cache-Control: public, max-age=0, must-revalidate`, so the browser rechecks them on every visit.
- Trainer web is a **Cloudflare Worker with static assets**, not Pages: `apps/trainer-web/wrangler.toml` sets `assets.directory = "./dist"`, `not_found_handling = "single-page-application"`, `binding = "ASSETS"`, and `run_worker_first = ["/api/*", "/i/*"]`. The Worker (`worker/index.ts`) only forwards `/api/*` and `/i/*`; everything else is served by the asset layer.
- Workers static assets read a `_headers` file from the assets directory ([Cloudflare docs](https://developers.cloudflare.com/workers/static-assets/headers/)). Vite copies `public/` into `dist/` at build time, so `apps/trainer-web/public/_headers` is the right place. That file is **not** applied to responses the Worker itself generates (`/api/*`, `/i/*`), which is what we want.
- **D-W14-39**, **D-W14-40**. W13 (trainer web restyle) is running in parallel and owns many `apps/trainer-web/src/**` files. This task must not edit `wrangler.toml`, `worker/index.ts`, `vite.config.ts`, or any file a W13 task owns. A new `public/_headers` and a new test are enough.
- Do not split the bundle. Record that as a later follow-up.

## Acceptance criteria
- [ ] `apps/trainer-web/public/_headers` sets, and only sets, these `Cache-Control` rules (one rule per path prefix, never two rules that both set `Cache-Control` on the same path — Cloudflare joins those and the result is wrong):
  - Hashed build assets: `/assets/*` → `public, max-age=31536000, immutable`.
  - HTML: `/`, `/index.html`, and `/*.html` → `no-cache`.
- [ ] Non-hashed files that Vite copies from `public/` (favicons, `site.webmanifest`, icons) must **not** receive the immutable header.
- [ ] SPA fallback paths such as `/clients` may keep the platform default (`public, max-age=0, must-revalidate`). Do not add a catch-all `/*` `Cache-Control` rule, because it would join with `/assets/*`.
- [ ] A test in the trainer-web package reads `public/_headers` and asserts the two kinds of rule above. The same test, or a second one, asserts that after `vite build` the file is present at `dist/_headers` (the built output the Worker serves). If a full production build is too heavy for the default `pnpm test` in this package, add a focused script the package test already runs, or run `vite build` in this new test and keep it reasonably short; say which in the PR.
- [ ] No change to `wrangler.toml`, `worker/index.ts`, routing, or the JS/CSS bundle.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
