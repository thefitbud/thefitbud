## Outcome
The trainee intake has no stray gap above long-text answers. Screen readers name an untouched sleep answer and its − / + buttons clearly. Tapping ✕ while a save is in progress doesn't start a second, competing save.

## Context
- These are the follow-ups from the Z14-46 reviews (#606, merged `1f18edd`); D-W14-45 … D-W14-47 still apply.
- **Gap:** IntakeScreen renders long-text questions through `Field` with `label=""` because the heading is drawn separately. `Field` (`apps/mobile/src/components/Field.tsx`) requires `label: string` and always renders the label `Text` with its bottom margin, which leaves an empty band above each box.
- **Sleep:** the untouched sleep placeholder ("—" with − / +) uses the generic labels "Decrease" / "Increase", and the "—" has no accessible name.
- **✕ during save:** tapping ✕ while a draft save is already running starts a second save, and the two can race on `expectedVersion`.
- This is mobile only, with no API change and no web change.

## Gap list
Written against `main` at `21923280`. Re-check on the latest `main`; drop what is done.
- `Field` has a required `label`; IntakeScreen passes `""`.
- The sleep placeholder value has no `accessibilityLabel`; its − / + labels don't name the question.
- ✕ is enabled while `saving` or `submitting` is true.

## Acceptance criteria
- [ ] `Field`'s `label` becomes optional. When it's absent or empty, no label `Text` (and no margin) is rendered, and `accessibilityLabel` falls back to the caller's `accessibilityLabel`, then `hint`. Every existing caller renders exactly as before (they all pass a label).
- [ ] IntakeScreen long-text questions pass no label to `Field` and set `accessibilityLabel` to the question text. The visible heading is unchanged.
- [ ] Untouched sleep placeholder: the "—" has the accessibility label "{question}: not answered". The buttons read "Decrease {question}" and "Increase {question}", where {question} is the field label (for example "Decrease hours of sleep"). The answered stepper keeps the shared NumberStepper as is.
- [ ] While a draft save or submit is running, ✕ is disabled (`accessibilityState.disabled`, dimmed). Android hardware back on step 1 does nothing until the save ends, and then opens the sheet as before. No second save starts.
- [ ] Z14-45 and Z14-46 behaviour is otherwise unchanged (one save then submit, banner on conflict, required check, Finish later sheet copy).
