## Outcome
A trainer clicks an exercise in Library › Exercises and gets its own page at `/library/exercises/:id`, laid out as in the approved mock. In the workout builder, an info button on a library row opens the same content in a right-side panel without leaving the builder.

## Context
- **D-W14-51** (approved mock), **D-W14-53** (no credit line on exercise screens), **D-W14-54** (no food detail), **D-W14-52** (dumbbell fallback). Data comes from Z14-51 through the api-client.
- The mock's design tokens are trainer web's own (`docs/design/v3-web/kit-v3-web.css`). Use existing UI primitives (Card, Chip, Button, side panel/drawer), not new styles where one exists.

## Acceptance criteria
- [ ] **Page:**
  - Breadcrumb "Library / Exercises / {name}" and a 44 px "Exercises" back link.
  - Title in sentence case as the library shows it.
  - Chips for source (FitBud, or "You" in the coach tint), main muscle and equipment.
  - Main column: start and end drawings side by side with "Start" and "End" captions, About, "How to do it" (numbered steps), then "Coaching cues" and "Common mistakes" side by side.
  - 360 px right rail: Details (Main muscle, Also works, Equipment) and Related exercises grouped Easier / Harder / Swap for. Each related row is a 44 px link with a 40 px thumbnail (drawing or dumbbell) that opens that exercise's page.
- [ ] **Narrow widths:** at 1180 and below the rail drops under the main column, and below 720 the two-column parts stack.
- [ ] **Missing data:** sections with no data are left out, never shown empty. With no drawing, a dashed tile shows the dumbbell and "No drawing for this exercise yet". No credit line anywhere (D-W14-53).
- [ ] **Editing:** FitBud exercises are read-only. A trainer's own exercise shows an Edit button that opens the existing edit form.
- [ ] **Builder panel:** an info button (accessible name "Details for {name}") on each exercise row in the builder library list opens the shared body in the side panel, with "Open full page". Esc and the close button return focus to the info button. Unsaved builder edits are untouched.
- [ ] **States:** loading uses the skeleton pattern. Not found shows "This exercise isn't in your library." with a link back. Errors go through `userFacingMessage` with Try again. No raw codes, IDs or enums; labels such as `lower_back` are humanised.
- [ ] **Keyboard and focus:** fully keyboard accessible with visible focus.
- [ ] **Captures:** 1440×900, 1180×820 and 1024×1366 under `qa-captures/z14-52/` for the goblet squat page, an exercise with no drawing, a trainer-owned exercise, and the builder panel. Compare with the mock. Run the W13 `textProblems()` checks.
- [ ] **e2e:** a Library row opens the page; a related link navigates; the builder info button opens the panel and Esc closes it.
- [ ] **Checks:** lint, typecheck, tests and banned-strings pass.

## Out of scope
Mobile detail screens, food detail (D-W14-54), video, "Used in N plans", and editing steps or cues. Working rules as in other Z14 specs; branch `claude/Z14-52-exercise-detail-web`.
