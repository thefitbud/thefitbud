## Outcome
With `EMAIL_PROVIDER=zeptomail`, OTP, invite and password-changed emails are sent through ZeptoMail from `FitBud <no-reply@thefitbud.com>` with reply-to `tech@thefitbud.com`, and a send failure surfaces as a stable error code without leaking the token or the message body.

## Context
- D-W2-1 (decided): ZeptoMail. Endpoint `POST https://api.zeptomail.in/v1.1/email`, header `Authorization: Zoho-enczapikey <ZEPTOMAIL_TOKEN>`, JSON body with `from {address, name}`, `to [{email_address {address}}]`, `reply_to [{address}]`, `subject`, `textbody`, `htmlbody`.
- D-W1-9 (decided): from `FitBud <no-reply@thefitbud.com>`, reply-to `tech@thefitbud.com`. I4a (W1) writes `EMAIL_PROVIDER = "zeptomail"`, `SYSTEM_EMAIL_FROM` and `SYSTEM_EMAIL_REPLY_TO` into the staging and production env blocks; this task only makes the code accept them.
- `ZEPTOMAIL_TOKEN` is a Worker secret Firoz sets (v14 CF2). It is never in toml, tests or logs; tests use a fake value like `test-token`.
- AU2 (W1) refuses `dev_sink` outside local; keep `DEV_SINK_REFUSED` as is.
- D-W2-8 (**Open**) asks who adds `MEDIA_PREFIX` to `Env` in `types.ts`, which this task owns in W2. Do not add it unless W2.md shows D-W2-8 closed as "I5 adds it"; the rest of this task does not depend on it.
