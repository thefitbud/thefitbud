## Outcome
Nothing a person sees says 'Nudge' or shows a bracketed error code, and every error message says what actually went wrong in friendly words.

## Context
- Diagnosis #11. D-W14-3, D-W14-15 ("Remind": "Remind Aarav", "Reminder sent", push title "{Coach first name} sent you a reminder").
- Runs last, after every other W14 PR is merged, so it can sweep their copy too.
- Internal identifiers (types, routes, DB columns, analytics, file names like `F20-triage-nudge.yaml`) stay as they are; only what a person sees changes.

## Gap list
- About 53 user-visible "nudge" strings in 27 files across mobile, trainer web and the API push title (`reminders.ts:1887-1893`, "nudged you").
- About 55 places render bracketed codes such as "(WO-SAVE)" next to messages.
- Some errors say "Something went wrong" where the cause is known (offline, session expired, already finished, upload too large).
- Written against `main` at `2c9819d3`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] Every user-visible "Nudge/nudge/nudged" becomes Remind wording (verbs: "Remind", "Reminder sent", "Send reminder"; push title "{Coach first name} sent you a reminder", fallback "Your coach sent you a reminder"); old notification rows are left as stored.
- [ ] No bracketed or bare error codes rendered on any screen; codes stay in logs and diagnostics only.
- [ ] Each error message names the actual cause from its code (offline, timed out, session ended, already finished, not allowed, file too big, server busy) in one or two friendly sentences with what to do next; the generic message is used only for unknown codes.
- [ ] `docs/spec/banned-strings.json` gains rules for user-visible "nudge" (case-insensitive), "Mark reviewed" and "Reviewed, still open" (D-W14-29; Z14-23 and Z14-26 removed them) and for a bracketed code pattern in rendered copy, with allowlists for internal identifiers; the banned-strings check passes.
- [ ] A list of every changed string (before → after, file) in `docs/qa/Z14-15/copy-changes.md`.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass; e2e and banned-strings green.

## Out of scope
- Product rules (AGENTS.md, never break): only the trainer resolves an exception; no auto-send (WhatsApp is a wa.me prefill the user sends); no percentages or streaks; dates read like "Wed 21 Oct", never ISO or raw enums; payments are tracking only; ended clients are read-only on server and UI.
- Error copy (D-W14-3): friendly copy only, never raw error codes, HTTP statuses, `err.message` or bracketed codes on screen; say what actually went wrong; keep a way forward. Map through `userFacingMessage`/`userFacingError`.
- Working rules: no remote or deploy commands; no secrets; one branch `claude/<ID>-<slug>`, one PR `<ID>: <summary>` off the latest `main`, updated by merging `main` (never rebase or force-push); never cancel an Actions run; never write the mention handle.
