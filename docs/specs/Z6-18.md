## Outcome
Every workout execution records who logged it, so the API and apps can tell trainee-logged from coach-logged workouts.

## Context
- In-person coaching, added to the beta by Firoz on 4 Nov 2026 (PLAN-v2 D-P2-15). Default rules R1–R3 (recommended, Firoz can override): R1 a trainer-started workout is read-only to the trainee, who sees "Logged by your coach"; R2 trainers are exempt from Z6-11 log-time limits for the log-workout form, backdate cap 7 days; R3 a coach-logged workout counts once toward adherence and streaks, keyed by the workout execution id, never double-counted.
- Written against `main` at c398f67. The implementer re-checks each item against the latest `main` before building (AGENTS.md).
- Add to `workout_executions` (migration 0004): `logged_by_role` text NOT NULL default `trainee` (`trainee` | `coach`), `logged_by_user_id` text NULL (FK `users`), `log_mode` text NULL (`live` | `form`). Existing rows backfill to `trainee`. No new set table; set rows stay in `set_executions`.
- Next free migration number after Z6-16, in the W6 serial migration lane. Remote application after merge by the batch's agent or FitBud UI (manual list P2).
- Trimmed from W14 Z14-5's migration (its `logged_by` idea, minus `session_entry_id`).
