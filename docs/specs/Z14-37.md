## Outcome
Things a trainee typed but that were held only in memory are not lost when the app restarts or when a full-screen cover unmounts the Workout tab: the **held session rating and note** (waiting for the finish to sync), and **unsaved input in Workout-tab sheets**. Nothing the trainee sees changes except that it is still there.

## Context
- The W14 Report lists memory-only state in three places: the held rating in `trainee/workout/rpeRating.ts` (kept in a module variable until the finish has synced), sheet input in the Workout tab that is thrown away when `TraineeShell` unmounts the tab under a cover (only a live workout is still kept mounted under an overlay), and settled sync notes. **This task discovers and fixes the first two, and does the third only if it is a few lines** (record it otherwise).
- After Z14-32 the held value is a rating **and a note** (D-W14-34); losing a typed note is worse than losing a tap on a number.
- Z14-34 (merged first) clears photo jobs on sign-out; this task clears its own stores in the same two places (`AuthProvider.endSession`, `clearSyncDataOnSignOut`). Sign-out already says unsent logs are dropped (TR-20f), so held ratings, notes and drafts are dropped with them; a server-ended session keeps them keyed by user id (Z12-41 rule).
- Use the same device store the sync outbox/photo jobs use (`apps/mobile/src/sync/**` storage helpers); no new storage dependency. Keys are owner-scoped.

## Acceptance criteria
- [ ] **Held rating and note:** `rpeRating.ts` writes its held value (rating, note, workout/execution id, owner id, time) to the durable store the moment the trainee taps Save while the finish is unsynced; it is restored after a restart and sent once the finish has synced (version read from the server as in Z14-12), then removed. A value for another owner is never read or sent. A value older than 72 h is dropped (the server's late window) with the neutral Z14-12 message, not an error.
- [ ] **Sheet drafts:** unsaved text/choices in Workout-tab sheets are saved to `sheetDrafts` (debounced, about 500 ms) keyed by owner and sheet id (plus the entity id), restored when the sheet reopens after a remount or restart, and cleared on Save, on Cancel and on sign-out. A draft older than 24 h is ignored. Never restored into a sheet whose entity is gone.
- [ ] Drafts and held values are cleared by explicit sign-out (`endSession("drop")`) and kept (owner-keyed) by a server-ended session; another user on the phone never sees them.
- [ ] No visible change when nothing is lost: no new copy, no "draft restored" banner. Performance: no write on every keystroke (debounce), no render loops.
- [ ] Store failures (storage full or unavailable) never block saving or sending; the in-memory path still works.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Decide-and-note
1. **Which sheets get drafts (recommended):** only those where typing is more than one tap (notes, free-text, numeric entry with several fields); choice-only sheets keep nothing.
2. **Settled sync notes (recommended):** skip unless the fix is under about 20 lines; record the finding.
3. **Key shape (recommended):** `fitbud.workoutDrafts.v1:<ownerId>:<sheet>:<entityId>`, one index key per owner for sign-out clearing.
