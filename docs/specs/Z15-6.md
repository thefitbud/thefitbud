## Outcome
Reminders and coach reminders pop up on screen and on the lock screen, the app shows the true permission state the moment the trainee comes back from phone Settings, and turning notifications on later registers the phone without a restart.

## Context
- Diagnosis #10. D-W15-13. Z15-4 sends `channelId` (v2 ids) and `priority: "high"`; this task creates those channels on the phone.
- D-W3-9 (carried): a new user's sign-in takes over the device token.
- `workout_live` (the live-workout channel) is created natively by Z15-5; never delete it.

## Acceptance criteria
- [ ] A foreground notification handler is set once at startup (`App.tsx`): pushes received while the app is open show as the in-app banner (TR-06h pattern, existing `ForegroundBanner`/notice queue) or the system banner; never silently dropped. Sound for reminders and coach reminders; none for the daily summary.
- [ ] `usePushPermission` re-reads OS permission on mount and on every return to the foreground (`AppState` → active); the trainee and trainer settings screens and the reminder setup screen use it, so the "Notifications are off" card disappears as soon as the trainee returns from Settings.
- [ ] When permission turns from not-granted to granted (any screen, or on foreground), the push token is registered at once (existing `sendRegistration`, idempotent); the trainer's "has turned off FitBud notifications" note clears after the next server read.
- [ ] Android: channels `workout_v2`, `meal_v2`, `checkin_v2`, `coach_v2`, `plan_v2`, `account_v2`, `clients_v2` created with IMPORTANCE_HIGH, `summary` stays DEFAULT, same names and descriptions; old ids (`workout`, `meal`, `checkin`, `coach`, `plan`, `account`, `clients`) deleted once; ids match Z15-4's server table (shared constant or a test that compares lists). Channels exist before the Android 13 permission prompt (keep `prepareForPermissionPrompt`).
- [ ] iOS: confirm the staging TestFlight build's APNs environment (`aps-environment` in the built entitlements vs `app.config.js` staging `development`) from the EAS build log or a simulator archive, and the Expo receipt of one staging push if the session can read it; record the finding. Change `app.config.js` only by stopping and reporting (it is Z15-5's file).
- [ ] D-W15-3 copy on every failure; `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
