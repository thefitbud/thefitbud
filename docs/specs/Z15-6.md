## Outcome
When something is slow or broken in production we see it within minutes: errors, slow requests, slow D1 queries, failed crons and failed pushes, each traceable to one request.

## Source (what exists)
- `wrangler.toml` already enables Workers Observability (production head sampling 0.2); Sentry wraps the Worker; manual step 15 (Sentry DSNs and `SENTRY_AUTH_TOKEN`). FitBud Tech's latency audit (24 Nov) could not read D1 metrics because its token was rejected.

## Acceptance (draft)
- [ ] Request id on every response and log line; per-request D1 query count and total D1 time logged (sampled) so slow screens are traced to queries.
- [ ] D1 insights checked weekly (top queries by time and rows read) with the command in the runbook; `PRAGMA optimize` after each migration (from Z14-4).
- [ ] Alerts (Sentry or Cloudflare notifications): 5xx rate, p95 latency over a threshold on hot routes, cron failures, queue DLQ growth, Expo push receipt errors; recipients named in the dashboard, not in the repo.
- [ ] Mobile: Sentry release health for both production apps (crash-free sessions), source maps uploaded by EAS; the W13 follow-up check that production EAS resolves `@sentry/cli`.
- [ ] Runbook: where to look first for "the app is slow" and "pushes stopped".
