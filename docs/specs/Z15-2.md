## Outcome
The trainee app is offline-first: after one online visit every tab paints from the phone, a log returns at once and shows in place as "Not sent yet", offline reads as a calm neutral state, and Today appears in one piece.

## Context
- Diagnosis #1 ("How the trainee local-first layer actually works today", "Inconsistent home"), #2, #3. D-W15-6 (trainee offline-first), D-W15-7 (expo-sqlite store, delivered by Z15-5 as an `AsyncKeyValue` adapter in `sync/storage.ts`), D-W15-9 (offline is neutral).
- Offline rules (AGENTS.md "Offline (mobile)"): write locally before enqueueing; one mutation UUID per logical action reused on retry; apply server results transactionally; advance the cursor only after applying; no universal last-write-wins.
- You may start at once; build the persistence step against the `AsyncKeyValue` interface and wire the SQLite adapter after Z15-5 merges (merge `main`). Merge after Z15-5.
- Workout and Progress tabs are not in `files_owned`: they read `getCached` from `dataCache.ts`, so hydrating that cache from the device store at sign-in covers their first paint without editing them.

## Gap list
- Writes: `sync/actions.ts:71` awaits `pushPending()` (30 s timeout, `engine.ts:475`); unknown reachability counts as reachable (`SyncProvider.tsx:52`); meal actions then `await refreshDay()` (`TodayTab.tsx:660`).
- Reads: `dataCache.ts:20` is an in-memory `Map`; nothing survives a kill; first paint after cold start is a skeleton on every tab.
- Queued logs are counted (`today/queuedLogs.ts:25-55`) but never applied to meals, rings or the "left" line; `getMeDay` failure becomes `null` (`TodayTab.tsx:371`).

- `ErrorBanner.tsx:5-15` is always crit; offline copy and "Couldn't refresh" use it (`TodayTab.tsx:423-424`, 58 call sites app-wide).
- Today renders independently-loading blocks around a partial skeleton (`TodayTab.tsx:683`, `:881`, `:1127`, `:1249`, `:1264`).
- Written against `main` at `2c9819d3`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] **Non-blocking logs:** `enqueueAndPush` returns after the local write and outbox insert; the push runs in the background and its verdict reaches the screen through the outbox state (refused rows still surface their message, D-W15-3). No meal or set action waits on the network to update the UI; the refresh after a log runs in the background (stale-while-revalidate).
- [ ] **Persistent snapshots:** day views, week models, workout lists, progress summary and check-in lists are written to the device store (owner-scoped key prefix, cleared on sign-out and role switch like the outbox) and hydrated into `dataCache` before the first tab renders. A cold start in airplane mode after one online visit paints Today, Diet, Workout and Progress with no skeleton. Snapshots older than 14 days are pruned.
- [ ] **Outbox overlay:** pending and in-flight meal/workout mutations are applied on top of the cached day (meal status, rings, "kcal left", "N of M logged", workout state) so the screen never contradicts "N logs waiting to send"; a pending meal row reads "Not sent yet · eaten as planned" (TR-06e). When the server answers, the overlay is replaced by the server state. Covered by a unit test with the inconsistent-home case (one queued meal, failed refresh).
- [ ] **Neutral offline (D-W15-9):** new `OfflineBanner` (neutral fill, `wifi-off` icon, no alert role) with "You're offline. Showing what was saved at {time}. Logs will send when you're back." `ErrorBanner` renders the neutral variant when given the offline message (or an `offline` prop) so all 58 call sites, trainer screens included, stop showing offline in red. "Couldn't refresh" stays crit only when the network was reachable (TR-06g, with Retry).
- [ ] **One Today skeleton (#2):** Today shows the TR-06f skeleton until the day bundle, plan state and week have answered or failed, then renders every block at once; with a cached snapshot it paints the snapshot immediately and never shows the skeleton. In-app banners wait for the first paint.
- [ ] **Kept tabs:** `TraineeShell` keeps visited tabs mounted (hidden, not unmounted) and does not refetch on a switch back if the data is younger than 30 s.
- [ ] Airplane-mode tests per AGENTS.md: create offline, kill and restart, reconnect, retry, duplicate delivery; F10 flows updated and passing.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Out of scope
- Product rules (AGENTS.md, never break): only the trainer resolves an exception; no auto-send (WhatsApp is a wa.me prefill the user sends); no percentages or streaks; dates read like "Wed 21 Oct", never ISO or raw enums; payments are tracking only; ended clients are read-only on server and UI.
- Error copy (D-W15-3): friendly copy only, never raw error codes, HTTP statuses, `err.message` or bracketed codes on screen; say what actually went wrong; keep a way forward. Map through `userFacingMessage`/`userFacingError`.
- Working rules: no remote or deploy commands; no secrets; one branch `claude/<ID>-<slug>`, one PR `<ID>: <summary>` off the latest `main`, updated by merging `main` (never rebase or force-push); never cancel an Actions run; never write the mention handle.
