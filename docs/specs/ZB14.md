## Outcome
A trainee or trainer can delete their account from the app or from a public web page, which ends their coaching relationships, removes or anonymises their data and revokes sign-in, meeting Apple 5.1.1(v) and Google Play's account-deletion rule.

## Context
- Covers master-list (v13) items BP1 (API part). Everything the implementer needs from those rows is pasted here.
- Before public release (not needed for the closed beta). Endpoints: `POST /account/deletion` (authenticated; requires a fresh OTP or password confirmation within 5 minutes) → schedules deletion; `DELETE /account/deletion` cancels within a 7-day grace period; a daily job performs it after the grace period.
- Effects: end every active relationship via the existing lifecycle (so exceptions close with `coaching_ended`); delete media in R2; delete device tokens, sessions, identities; anonymise rows that other users' records need (trainer notes, check-in reviews keep the trainer side, the trainee name becomes "Deleted user"); remove the Firebase user via Admin REST (secret already used by push: no new secret).
- Public web page for the Play listing: `GET /account/delete` (HTML, no data) explains how to delete and links to the app; it is served by the API (`account-deletion-page.ts`).
- Q-W6-2: grace period length (7 days recommended) and whether trainers with active clients must end them first (recommended: yes, block with a clear message).
