## Outcome
The trainee's check-in shows the pinned form's real questions and sends only what the trainee answered, never an invented `"OK"`; the trainer sees those same answers on phone and web; and choosing the FitBud global form in web Configure pins the version new assignments use. This is a behaviour fix, not a redesign.

## Context
- Product direction: Firoz, 7 Nov 2026 (D-W6-42). Background: D-W6-18 (mobile invents `"OK"`, trainer review shows it), D-W6-19 (web Configure pins the global form's latest version), D-W6-41 (order Z6-6 → Z6-2b → Z6-2c → Z6-2 → Z6-7).
- After Z6-2b, `wellbeing` is required only when the pinned form marks it required; v2's standard questions are all optional. The submit contract no longer needs a made-up value.
- **Questions to render (Firoz):** weight; waist, hips, chest, arm and thigh; front, side and back photos; 1–5 ratings for energy, sleep quality, stress and hunger; notes; plus any custom questions without a key. The screen renders whatever the pinned form (`getCheckinForm`) contains, in its order, with each question's own label, unit (`unit` for `other` measurements, kg or cm otherwise) and control. It keeps today's steps, grouping, styles and photo-intent behaviour; no new layout.
- **Answers to send:** one entry per question the trainee answered, keyed by the question id in `fieldAnswers`. `wellbeing` is sent only when the pinned form has a `wellbeing` question (v1) and the trainee typed it; label guessing ("wellbeing", "feeling") goes. Unanswered questions are left out, not sent as null or a placeholder. The same rule applies to draft save, the conflict retry and the queued (outbox) submit.
- **Form load failure (recommended default, D-W6-34):** today, when `getCheckinForm` fails, the screen builds its own three-question form (`"How are you feeling?"`, required) and can submit it. That invents questions the pinned form may not have. Instead the screen shows the load error with a retry and keeps any saved draft; it offers no submit until the pinned form loads.
- **Review screens show the real answers, in the pinned form's order**, using Z6-2b's shared core answer-list helper (both apps get the same list). Unanswered questions are skipped, as the frames show only answered rows (recommended default, D-W6-34). Measurements show their unit; ratings show the number (web as in 163/164, mobile "N of 5" tiles as in 75); photos keep their current "Photo noted" / photo tiles. A v1 check-in where the trainee typed `wellbeing` still shows it under that question's label. Stored answers are shown as stored; nothing is rewritten.
  - **Mobile trainer review (frame 75):** the rating tiles come from the pinned form's 1–5 questions that were answered (v2 has four; the tiles wrap in the same style, recommended default) instead of a fixed Energy/Hunger/Stress list; the text rows come from the pinned form's text questions instead of the fixed "What went well? / What was hard? / Anything for …?" list and its `wellbeing` fallback. Weight and waist tiles keep their current "since" lines from stored measurements; other answered measurements (hips, chest, arm, thigh) appear in the same tile style with value and unit, with no delta.
  - **Web review (frames 163, 164):** the answers list already follows the pinned form. Fix: a measurement question no longer falls back to `bodyWeightKg` unless it is the weight question; every measurement shows its unit (kg, cm, or the question's unit); unanswered questions are not listed.
  - **Trainee sent and reviewed (frames 100, 101):** wherever these states show what was sent, they show the real submitted answers (101's "What you sent" list in form order; 100's weight and photo count from the submitted answers), never `wellbeing` `"OK"`. Parts of these frames that need data the current screens do not read stay as they are and are listed in the PR as frame gaps, not invented (recommended default, D-W6-34).
- **Web Configure fallback only (frames 148, 149):** when the trainer picks the FitBud global form, the page pins `GLOBAL_CHECKIN_FORM_VERSION_ID` (the version new assignments use, from `@fitbud/core`), not the global template's `latestVersionId`. Same rule as Z6-6's fork fix (D-W6-41 (2)). Trainer-owned forms keep pinning their latest version. The check-in summary line finds the global form by the same rule. Do not rebuild Coaching setup or touch the form builder.
- Test data: the demo seed has no v2 form until Z6-2 merges. For tests and screenshots, create a trainer-owned form with v2's keyed questions plus one custom question through the form-template API on the local seed and assign it with the preferred-form route; do not change the seed. Say in the PR how the screenshot data was made.
- Error handling follows AGENTS.md "Client error handling": no catch shows a cause it did not check; only an `ApiClientError` message is shown verbatim.

## Acceptance criteria
- [ ] The trainee check-in renders exactly the pinned form's questions, in order, including custom unkeyed questions, with the right unit and control for each.
- [ ] Submitting a v2-shaped form with only weight and energy answered sends `fieldAnswers` with those two entries and no `wellbeing`; the server accepts it (200).
- [ ] No code path sends `"OK"` or any other value the trainee did not enter (submit, retry, draft, queued submit); a unit test proves it for each path.
- [ ] A v1 check-in still sends the typed `wellbeing` and still gets the server's `CHECKIN_ANSWERS_INCOMPLETE` when it is blank.
- [ ] When the pinned form cannot load, no invented questions are shown and submit is not offered; retry loads the form.
- [ ] Mobile trainer review (75) and web review (163/164) list the same answered questions in pinned-form order, with units, and show no `wellbeing` line for a form without that question.
- [ ] Trainee sent (100) and reviewed (101) states show only real submitted answers.
- [ ] Web Configure: choosing the FitBud global form pins `GLOBAL_CHECKIN_FORM_VERSION_ID`, both in a draft and on an active configuration (preferred-form call), even when the global template has a newer version; a trainer form still pins its latest version.
- [ ] Visual check passes (below); `pnpm lint`, `pnpm typecheck`, `pnpm test` pass; the banned-strings e2e scan passes.
