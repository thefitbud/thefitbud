## Outcome
A 1180-wide desktop window or an iPad with a pointer meets the 44 px tap-target rule as an iPad does. Firoz/FitBud UI decision D-W13-28; follow-up named by the W13 coordinator ("Tap targets at 1180").

## Problem
`styles/tap-targets.css` applies 44 px only at `(max-width: 1024px), (pointer: coarse)`. At 1180x820 links such as Coach notes Edit, Delete and Make private, Overview "Open plan", the review panel's small text actions and the "Custom range" link are under 44 px (`qa-captures/w13-6/W-03-client-overview-rail-1440x900.png` shows them at 1440; at 1180 they are the same size).

## Acceptance criteria
- [ ] The media query becomes `(max-width: 1280px), (pointer: coarse)` for the whole block (and the matching `ipadBlock()` lookup in `tap-targets.test.ts`); update the comments in `styles/workspace.css`, `styles/clients.css`, `components/workspace/workspace-header.css` and `components/side-panel/side-panel.css` only if they quote the 1024 breakpoint (comment-only edits are allowed; no other change to those files).
- [ ] Nothing grows into an oversized visible box: checkboxes and radios keep their normal visible size with a 44 px hit area (label padding or `::before`), as W13-15 does for "{First} can see this note"; text links get 44 px height through padding with unchanged visible text; icon buttons 44x44.
- [ ] The new `ui-btn` family, `ui-seg`, `ChipMenu`, `OverflowMenu` triggers, chip filters, table row actions and tabs are covered (measure, do not assume: the file only names legacy `.button-*` classes). Add selectors where a measured control is under 44 px.
- [ ] At 1280x800 and 1180x820 and 1024x1366: the shell sidebar and rail, Home, Overview, Activity, Progress, Check-ins, Templates, the builders and Settings show no clipping, no overlap and no window scroll after the change; at 1440x900 nothing changes (assert with unchanged capture dimensions and `textProblems()`).
- [ ] New e2e `w13-22-tap-targets.spec.ts`: at 1180x820 visit those screens and assert every visible `a, button, [role=button], [role=tab], input, select, label[for]` has a hit box of at least 44 px in the smaller dimension (allow an explicit allow-list for inline text links inside a paragraph, listed in the spec with the reason); fail with the selector list.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test`, the web e2e pass.

## Tests to add
