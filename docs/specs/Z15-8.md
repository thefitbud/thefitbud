## Outcome
However fast or often the trainee taps, one workout produces one finish and one row per set; sets logged from the lock screen or the Android notification land in the open workout right away, and a late one never turns into an error on the save screen.

## Context
- Diagnosis #13 and #9 (JS side). D-W15-12. Z15-7 makes the server idempotent; Z15-5 adds the native event when a lock-screen row is appended; Z15-2 makes `enqueueAndPush` non-blocking.
- Offline rules (AGENTS.md): one mutation UUID per logical action, reused on retry.

## Gap list
- `ActiveWorkoutScreen.tsx:678-699` `finishWorkout()` and `:701-718` `discardWorkout()` have no in-flight guard; each call mints a new mutation id.
- Set rows use `expectedServerVersion: execution.recordVersion` from the render closure (`:563-571`).
- `liveActivityOutbox.ts` drains only on foreground/workout tab; rows for a finished workout are sent and refused.
- "(WO-SAVE)" codes on screen (`:576`, `:652`).
- Written against `main` at `2c9819d3`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] Finish, Discard, Skip workout and Start are guarded: a ref-based in-flight lock plus disabled buttons; the mutation id for "finish this execution" is derived from the execution id (stable), so a second tap or a retry reuses it. A double tap test produces exactly one `workout.complete` row.
- [ ] Discard/skip is not offered (and is a no-op) once the execution is finished locally.
- [ ] Set rows read the latest execution from a ref for `expectedServerVersion` (or omit it where the server does not need it); a correction of the same set reuses that set's mutation id.
- [ ] Lock-screen and notification "Log set" rows drain immediately on Z15-5's native event while the app is running, and on foreground otherwise; a row for an execution already finished locally is dropped with a sync-status note (never sent); the existing dedupe by row key stays.
- [ ] The save/summary screen never shows a sync refusal for these cases: `WORKOUT_ALREADY_FINISHED` verdicts are shown as resolved in the sync status with friendly copy (D-W15-3); "(WO-SAVE)" and similar codes removed from this task's files.
- [ ] Tests and F03/F06 flows updated; `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
