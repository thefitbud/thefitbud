## Outcome
The mobile app has v3 colours in light and dark, follows the system theme live with no in-app switch, uses Inter with the v3 type scale, and every shared primitive takes its colours from tokens.

## Context
- W12-PROMPT Z12-36; D-W12-12, D-W12-29. Starts after Z12-35 merges (D-W12-21a).
- Source: `docs/design/v3/kit-v3.css` and the "v3 additions" block in `docs/design/v3/src/kit.css`; spec `DESIGN-SYSTEM-v3.md`.
- The anchor mocks above are for primitives only (colour, type, radius). Screens migrate in their own tasks; here existing screens keep rendering correctly in light and no test regresses.
- Inter through `@expo-google-fonts/inter` with the existing `expo-font`/`FontsProvider` (JS only). If Inter needs native config, the config goes to Z12-57 and the JS loads it now.

## Gap list
- `packages/tokens/src/tokens.ts` has v2 values; `packages/tokens/scripts/build-css.ts` generates CSS from TS, not from `kit-v3.css`.
- No `ThemeProvider`/`useTheme()`; no dark palette in the app.
- `apps/mobile/src/providers/FontsProvider.tsx:53` loads Satoshi; `components/Text.tsx` applies Satoshi.
- Primitives in `apps/mobile/src/components/` (Screen, Text, Button, PrimaryButton, BottomSheet, StatusChip, Snackbar, SegmentedControl, AppTopBar, Field, ErrorBanner, SwipeActionRow, OverflowMenu) and `packages/ui-mobile/src/{theme,typography}.ts` use fixed colours.
- Written against `main` at `3c227e12b`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).
