## Outcome
Trainer web and the apps can show the real exercise drawing for a library exercise. Each exercise in the library payload says whether it has a drawing and carries its credit (author, licence, licence URL). An image route returns the drawing bytes for a library exercise from the R2 media bucket. A script loads the 919 drawings from the repo into a bucket: local for development, and staging or production when Firoz runs it. No UI change in this task: Z14-49 uses it on trainer web.

## Context
- Firoz, 28 Nov 2026: trainer web's Library and template builder screens show coloured gradient tiles (`LibraryThumb`) for exercises and foods. Exercises should use the drawings from the bucket, and foods should show no image. This moves the post-MVP item "exercise drawings, R2 media and contract fields" from W16 into W14 (**D-W14-49**). The exercise and food detail screens stay out of this task (**D-W14-51**, open question).
- **The drawings exist, but nothing serves them.** `apps/api/seed/library/incoming/exercise-base-2026.10.21-v3/media/<slug>/` has 919 CC BY-SA drawings for 460 exercises. `exercise_library_media` rows (seeded by `sql/03b_exercise_base.sql`) carry `storage_key` = `exercises/<slug>/<n>.<ext>`, plus `author`, `licence`, `licence_url`, `attribution` and `sort_order`. There is no route that serves them, no contract field, and no script that puts them in R2 (`MEDIA` binding: `fitbud-media` locally, `fitbud-media-nonprod` on staging, see `apps/api/wrangler.toml`). Whether Firoz has already uploaded them to staging is unknown, so the route must behave well when the object is missing.
- Credits rule: `docs/spec/credits-and-licences.md` (credit wherever a drawing appears; per-file credit comes from the data).
- AGENTS.md: raw object keys are never authorization; R2 metadata lives in D1; provider code stays in the API; static error messages; stable error codes.

## Acceptance criteria
- [ ] **Contract:** exercise library items gain `media: { id, frame, author, licence, licenceUrl, attribution }[]` (ordered by `sort_order`; empty when none) and `thumbnailMediaId: string | null` (the first illustration). No storage key is exposed. Foods are unchanged. Old clients ignore the new fields.
- [ ] **List and detail payloads** fill these fields from `exercise_library_media` without an N+1: one batched query per page. List performance stays within the existing route's limits (add a test that a page of 50 makes at most one extra query).
- [ ] **Image route:** `GET /library/exercise-media/:mediaId` for an authenticated trainer or trainee. It looks up the row by id in D1 and reads `mediaKey(env, storage_key)` from `MEDIA`. Library media is global (not owned), so any signed-in user may read it; unauthenticated requests get 401. Unknown id → 404 `LIBRARY_MEDIA_NOT_FOUND`. A row whose object is missing in R2 → 404 with the same code, plus one Sentry-safe log line (id only). Success returns the bytes with the stored content type and `Cache-Control: private, max-age=86400, immutable` (drawings never change under the same id). Error bodies are static text.
- [ ] If the route needs to work from an `<img>` tag (cookie or bearer auth), follow how the trainer web already loads protected images (check `routes/files.ts` signed URLs); if a signed URL is needed, add `thumbnailUrl` signed the same way and say so in the PR.
- [ ] **Upload script:** `pnpm --filter api media:upload-exercises -- --target local|staging|production [--dry-run]`. It walks the seed `media/` folder, maps each file to its `storage_key`, and puts it with the right content type, skipping objects that already exist with the same size. `local` writes to the local wrangler R2 state (`--persist-to .wrangler/state`, matching `db:reset`). `staging` and `production` only print the exact `wrangler r2 object put` commands, or run them only when `--yes` is passed: **agents never run them** (AGENTS.md). `--dry-run` lists counts and missing files. It is idempotent.
- [ ] `pnpm db:reset` (or a documented one-line follow-up in LOCAL_TESTING.md) leaves local R2 with the drawings, so local trainer web shows them.
- [ ] `manual-steps.md` gets one step for Firoz: run the script for staging after this merges, then for production at the next production deploy.
- [ ] `pnpm lint`, `pnpm typecheck` and `pnpm test` pass, plus the API authorization tests for the new route.
