## Outcome
The QA workflow runs nightly and on demand only, so pull requests no longer queue QA runs on the shared runners.

## Context
- From the W10 report (Follow-ups, "Process and CI"): `qa-scripts` stays off `main`'s required checks permanently (Firoz, 12 Nov).
- `qa.yml:126-143` triggers on `schedule`, `workflow_dispatch` and `pull_request: branches [main]`. The first job classifies pull requests by changed paths; with no `pull_request` trigger, that branch of the logic is dead. Remove it minimally: the trigger, plus any `if:`/`concurrency` expression that only tests `github.event_name == 'pull_request'`, where removal is clearly safe. Leave the `changes` job's outputs for schedule/dispatch working; no `needs.changes` reference may dangle. When in doubt, leave dead-but-harmless logic and list it.
- Z11-1's `design-review.yml` triggers on `workflow_run` of this workflow (completed, branch `main`). `workflow_run` keys on the workflow **name**, so the `name:` line must not change. Depends on Z11-1 being on `main` so the check below is real.
