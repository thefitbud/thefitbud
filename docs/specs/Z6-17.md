## Outcome
Archived accounts past `purge_after` are deleted for good by the existing cron, safely and resumably, and support has a runbook for "delete my account now" emails.

## Context
- Split out of Z6-14 (formerly ZB14) on 4 Nov 2026 to keep one task per PR at W3/W3b size (PLAN-v2 D-P2-6). Account deletion is beta scope (Firoz, 4 Nov 2026, D-P2-3). Rules: D-W6-7, D-W6-8 in `docs/specs/batches/W6.md`.
- **Purge:** `runAccountPurge(env, now)` in `apps/api/src/jobs/account-purge.ts` (stub from Z5-4, already called from the existing cron) picks archived users with `purge_after <= now`, a few per run, and for each: deletes media in R2, identities and remaining tokens; anonymises rows other users' records need (trainer notes and check-in reviews keep the trainer side; the person's name becomes "Deleted user"); removes the Firebase user via Admin REST (secret already used by push, no new secret); finally deletes or anonymises the users row. Idempotent and resumable after a crash.
- **Permanent deletion now:** the user emails tech@thefitbud.com from the address or phone on the account. Support verifies the sender matches the account, then follows `docs/runbooks/account-deletion.md`: archive the account if it is not archived (Z6-14's flow), set `purge_after` to now with one `wrangler d1 execute <db> --remote` statement (by user id, no personal data in the command history), and confirm by reply once the next purge run reports it. No admin endpoint and no new secret. The implementer writes the runbook; support (FitBud UI on the box) runs it.

## Acceptance criteria
- [ ] Only archived users with `purge_after <= now` are purged; active and not-yet-due archived users are untouched (test).

- [ ] Other users' records survive with "Deleted user" in place of the person; no personal data in logs.
- [ ] The runbook covers verify sender → archive → set `purge_after` → confirm, with no personal data in commands.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
