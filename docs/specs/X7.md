## Outcome
The trainer's "open on the web" link in the mobile app goes to `https://app.thefitbud.com` (production) or `https://app-staging.thefitbud.com` (staging builds), never to the old default host.

## Context
- D-W2-7 (decided by Firoz, 31 Oct 2026): `app.thefitbud.com` is trainer web (served by the web Worker, WD1), `app-staging.thefitbud.com` for staging, `api.` / `api-staging.` for the API, and `thefitbud.com` for the landing page and sign-in redirect. No other trainer-web host is used.
- Code references (read-only today): `apps/mobile/src/trainer/MoreScreen.tsx:12-13` sets `TRAINER_WEB_URL = process.env.EXPO_PUBLIC_TRAINER_WEB_URL ?? "https://coach.thefitbud.com"`; `apps/mobile/src/trainer/MoreScreen.tsx:66` opens it with `Linking.openURL`. No other app code mentions `coach.thefitbud.com` (other "coach." matches are sentences ending in the word coach).
- X6 (W1) creates `apps/mobile/eas.json` with profiles `development`, `preview` (staging) and `production`, each with `APP_VARIANT` and `EXPO_PUBLIC_API_BASE_URL`. Add `EXPO_PUBLIC_TRAINER_WEB_URL` next to them; change nothing else in that file.
