## Outcome
When a client fixes or removes a meal entry within their 24 hours, the coach finds out: a push and an in-app notification ("Aarav edited lunch · 610 → 690 kcal · changed portion") that opens that client's diet day on the meal, a quiet "Edited" tag on the row with who changed it, when and what it was before, a "Removed" activity row, and a "Client log edits" toggle to turn the notifications off.

## Context
- D-W14-22 (e) and **D-W14-23** (confirmed by Firoz, 24 Nov 2026: notify trainers). Z14-11 stores and pushes `trainer_client_log_edited` (payload `{ entryId, action, mealName, mealDate, fromKcal, toKcal, fromOutcome, toOutcome, fields }`, category `clientLogEdits`, 10-min per-entry debounce) and exposes `lastEditedByRole`, `lastEditedAt`, previous value and the removal item; no new endpoint.
- Patterns to copy: `trainer_meal_times_changed` end to end (core copy, mobile `copy.ts`/`routing.ts`/`resolveRoute.ts`, `mealTimesChanged` in both settings screens); `WorkoutPanel.tsx:11-20` ("Edited by coach · {day}") for the panel line. Tags are neutral (fill / ink2), never an alert colour.
- Z14-15 does the final wording pass later; write the copy below as is.

## Acceptance criteria
- [ ] **Copy** (`packages/core/src/notification-copy.ts`, used by the API push, the mobile inbox and the web bell; D-W14-23 f): edited → title "{First} edited {meal}" (+ " · Thu 12 Nov" when `mealDate` isn't today in the trainer's zone), body "{from} → {to} kcal · {changed portion | ate out | logged it themselves}", "Changed {portion | foods}" when kcal is unchanged, "Changed the note." for note only; removed → "{First} removed their {meal} log", body "{Day} · was {kcal} kcal{, ate out}. It's back to not logged." Meal names lower case in titles ("lunch"), first name only, numbers with thousands separators, no codes, no "nudge".
- [ ] **Tap (D-W14-23 g):** trainer app push or notification row → new route kind `{ kind: "clientDiet", relationshipId, date, entryId? }` → `DietDayReviewScreen` for that client and date with `DietMealSheet` open on the entry (removed entry: the day, nothing open); a wrong entity type falls back to the attention list like the other types. Trainer web bell item → `/clients/{relationshipId}/activity?date={mealDate}&entry={entryId}` with the meal panel open.
- [ ] **Web bell:** unread `trainer_client_log_edited` rows appear with the shared title (latest 5, newest first) next to asks and check-ins. If the trainer's inbox rows can't be read through an existing endpoint, take the recommended option: Activity only, note it in the PR.
- [ ] **Settings (D-W14-23 c):** "Client log edits" · "When a client edits or removes a meal log", on by default, in the trainer app Notifications screen (TM-07b2, after "Check-ins sent") and in trainer-web Notification settings, saved to `clientLogEdits`. Off: no push, no inbox row; the tags still show.
- [ ] **Markers:** trainer web Activity and the client day: a meal row last edited by the client shows a small neutral **Edited** tag and an unread dot while the notification is unread; the meal panel shows "Edited by {first name} · Sat 14 Nov, 2:05 pm" and "Was 610 kcal · {previous detail}" (TM-09f). A removal is an Activity row "{First} removed their {meal} log ({day}) · was {kcal} kcal" with a neutral **Removed** tag (TM-09e); the meal then reads as not logged. Trainer app `ActivityMealSheet`, activity model and `DietMealSheet`: the same.
- [ ] Coach edits keep today's "Edited by coach" wording and never notify; nothing changes for entries the client never edited.
- [ ] Copy follows D-W14-3; `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
