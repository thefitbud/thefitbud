## Outcome
A trainer reviewing a client knows at a glance what each button does and how to move on: one card, one obvious next action, words that say what happens, the client's name opens their profile, and the same review looks the same whether opened from Attention or from the profile.

## Context
- Diagnosis #22, #23. **D-W14-29** (review panel wording and structure), D-W14-15 ("Remind"), D-W14-27, **D-W14-28** (mock gate). Use the approved frame files listed in `docs/design/mockups/z14-17/README.md` if they differ from the names above, and the wording Firoz approves there (D-W14-29 records it).
- Today: Nudge… / Mark reviewed / Resolve… explained only by a caption (`ReviewSheet.tsx:409-441`, `:478-483`); a stepper, dashes and a "Next item" button (`:315-376`, `:468-476`) whose meaning changes (`:158-162`); a second review UI on the profile path (`ExceptionReviewScreen.tsx:424-480`); a ⋯ menu that repeats the profile (`sheets/MoreSheet.tsx:86-106`).
- Server behaviour does not change: "Noted, keep open" is the existing acknowledge; "Resolve…" the existing resolve with outcome; "Remind" the existing nudge push. Only the trainer resolves; no auto-resolve.
- Screens: the review sheet (open, seen, resolved, all done) and the exception screen.

## Acceptance criteria
- [ ] One `ReviewCard` (title, what happened, Planned/Logged/Reminder rows hidden when empty, never "—") and one `ReviewActions` used by both `ReviewSheet` and `ExceptionReviewScreen`.
- [ ] Actions per state exactly as the approved frames: open: "Remind {first}" (only for remindable types), "Noted, keep open", "Resolve…" (primary); after Noted: a state line "Noted · still open" with Undo, Remind available, Resolve primary; resolved: read-only outcome with Undo where it exists today. No explanatory caption; no "…" except on actions that open a sheet. "Resolve…" opens the short confirm sheet that asks for the outcome (Talked to {first} · Plan adjusted · No action needed, optional private note, "Resolve"), as RP-03. "Mark reviewed" appears nowhere in the trainer app afterwards (D-W14-29, confirmed by Firoz 24 Nov 2026).
- [ ] Moving: the "1 of 3" stepper is the only control to change item; the dashes are a passive indicator; the extra "Next item" button goes; "Next client: {name}" appears only on the all-done summary, next to "Back to Attention".
- [ ] The ⋯ menu goes from both screens; "Add note" (the note sheet) and "WhatsApp" (wa.me, no template, the trainer sends) are two small text actions under the card; the avatar and name open the profile (`ClientAvatar`).
- [ ] Undo windows, idempotency keys, offline disabling, ended-client read-only and the resolve conflict recovery work exactly as today (existing tests pass, updated only for copy and structure).
- [ ] The Android back rules of D-W14-24 hold for the sheet and every sub-sheet.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Out of scope
- Product rules (AGENTS.md, never break): only the trainer resolves an exception; no auto-send (WhatsApp is a wa.me prefill the user sends); no percentages or streaks; dates read like "Wed 21 Oct", never ISO or raw enums; payments are tracking only; ended clients are read-only on server and UI.
- Error copy (D-W14-3): friendly copy only, never raw error codes, HTTP statuses, `err.message` or bracketed codes on screen; say what actually went wrong; keep a way forward. Map through `userFacingMessage`/`userFacingError`.
