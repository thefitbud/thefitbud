## Outcome
On a shared phone, a trainer who signs in, offline or online, never sees the previous trainer's Attention list, client list or client status from the local cache.

## Context
- From the W10 report (Follow-ups, "Privacy and data", first task of the next batch). Privacy bug: **merges before any other W11 code PR** (D-W11-F1).
- `apps/mobile/src/trainer/cache.ts` stores JSON under fixed keys in `localStorage` (web) or a module-level `Map`. Callers: `AttentionTab.tsx:129` (`trainer:attention`), `ClientsTab.tsx:181` (`trainer:clients`), `ClientStatusScreen.tsx:172` (`trainer:client:${relationshipId}`). None of the keys carries the user, and nothing clears them on sign-out, so an offline read after a different trainer signs in serves the previous trainer's snapshot.
- Fix inside the cache module so the three callers do not change (they are not owned here): the module holds the current owner id (`setTrainerCacheOwner(userId | null)`), prefixes every key with it internally, returns `null` and writes nothing while no owner is set, and `clearTrainerCache()` removes every `trainer:` entry from both stores (including any legacy unprefixed key). `AuthProvider.tsx` sets the owner from the authenticated `me` user id once known, and calls `clearTrainerCache()` and `setTrainerCacheOwner(null)` in `signOut` and in the refresh-refused path that clears the session.
- Ownership is never taken from cached data: the owner comes only from the server's `me` response.

## Gap list
- `apps/mobile/src/trainer/cache.ts`: keys not scoped to a user; no clear function.
- `apps/mobile/src/auth/AuthProvider.tsx` `signOut` (~l.454) and the session-clear paths (~l.266, l.350, l.442): the trainer cache is not cleared.
- Written against `main` at 5c457c1. The implementer re-checks each item against the latest `main` before building (AGENTS.md).

## Acceptance criteria
- [ ] Trainer A writes the attention snapshot; after sign-out and sign-in as trainer B, `readTrainerCache("trainer:attention")` returns `null` (both web `localStorage` and the memory store).
- [ ] While signed in as A, A's own snapshot still reads back (offline Attention keeps working).
- [ ] Sign-out removes every `trainer:` key from `localStorage` and the memory map, including legacy unprefixed keys written by older builds.
- [ ] With no owner set, reads return `null` and writes are dropped.
- [ ] A refused refresh that clears the session also clears the cache.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
