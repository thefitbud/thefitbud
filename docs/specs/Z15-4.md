## Outcome
The database keeps the statistics it needs, the reminder job uses an index, expired rows are cleaned daily, the Worker can run next to the database, and Android pushes arrive on the right channel at high priority.

## Context
- Diagnosis #1 (FitBud Tech's index audit) and #10 (server push payload). D-W15-13 (channel ids and priority), D-W15-18 (one migration, next free `0042`).
- Remote commands are Firoz's (AGENTS.md): this task writes the scripts, the migration and the runbook note; Firoz runs them on staging and production.

## Gap list
- `PRAGMA optimize` is never run; the current-plan lookup scans all plan versions without statistics.
- The reminder job scans the whole `notifications` table every 5 min (FitBud Tech; find the query in `apps/api/src/jobs/reminders.ts` / `domain/reminders.ts` and index its predicate).
- Expired rows are never deleted: idempotency replies, sync records, web sessions, login codes, old read notifications.
- `schema.ts` index list differs from the migrations; ~9 duplicate indexes.
- `wrangler.toml` has no `[placement]`.
- `lib/expo-push.ts:155-160` sends no `channelId` and no `priority`.
- Written against `main` at `2c9819d3`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

- [ ] Migration `0042_*` adds the index the reminder job needs (verified with `EXPLAIN QUERY PLAN` in a test) and drops duplicate indexes only where an identical one remains (no data change). `schema.ts` matches the migrations; the migration-chain test passes.
