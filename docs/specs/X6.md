## Outcome
Firoz can make an EAS dev build for his phones (task X3), and staging and production variants of the app can be installed side by side, each pointing at its own API.

## Context
- Decision D-B12 (31 Oct 2026, Claude's recommendation adopted in v14) and D-W1-3 (Firoz, 30 Oct 2026): two app variants.
  - production: bundle id / package `com.thefitbud.mobile`, display name `FitBud`, API `https://api.thefitbud.com`, Firebase project `thefitbud-prod`.
  - staging: `com.thefitbud.mobile.staging`, display name `FitBud Staging`, API `https://api-staging.thefitbud.com`, Firebase project `thefitbud-staging`.
  - development: dev client (`expo-dev-client` is already a plugin), local API or staging API.
- Domains (D-B10, Firoz 31 Oct 2026): mobile calls `api.thefitbud.com` / `api-staging.thefitbud.com` directly.
- `apps/mobile/eas.json` (new) has profiles `development` (developmentClient, internal distribution), `preview` (staging variant, internal distribution) and `production` (production variant, store distribution), each setting `APP_VARIANT` and `EXPO_PUBLIC_API_BASE_URL`.
- `app.config.js` reads `process.env.APP_VARIANT` (`production` | `staging` | `development`) and sets name, bundle id, package, and the App Group.
- Live Activity App Group per variant: `group.com.thefitbud.mobile` (production) and `group.com.thefitbud.mobile.staging` (staging and development). Today the group is hard-coded in three places (Gap list); make the plugin and target config take it from the config, and make the Swift `suite` read it from the app's Info.plist key `FitBudAppGroup` written by the plugin.
- `google-services.json` per variant comes from Firebase and is loaded through an **EAS file environment variable** (`GOOGLE_SERVICES_JSON`), never committed. `app.config.js` sets `android.googleServicesFile` from that variable when present.
- Expo Go cannot run this app (SDK 52 with native targets); the guide uses a dev build.
- Guide `docs/runbooks/physical-device.md`: prerequisites (Expo account, Apple/Google accounts), `eas build --profile development --platform ios|android`, installing on device, pointing at local API over LAN or at staging, the EAS file env var for `google-services.json`, where secrets live (EAS, never the repo or chat), troubleshooting. Firoz runs the build (X3); agents never run `eas build`.
- Agents cannot compile Swift on Linux: the PR lists a device check for Firoz (Live Activity still appears on the dev build).
