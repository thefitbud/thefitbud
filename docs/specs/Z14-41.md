## Outcome
A held session rating and note, saved on the phone after a force-quit, are sent as soon as the trainee's app is open and in the foreground — not only when they open the Workout tab. The 48-hour edit window is still respected, and a resumed send still reuses the saved idempotency key. Sheet drafts stay as they are: they come back when the sheet reopens, and are not sent on their own.

## Context
- Z14-37 already persists the held rating and note (`pendingFeedbackStore`) and exposes `resumeHeldWorkoutFeedback` in `apps/mobile/src/trainee/workout/rpeRating.ts`. On `main` at `ddd48f22` that resume runs from `WorkoutTab.tsx` when the Workout tab mounts. If the trainee never opens Workout within 48 hours, the hold is dropped unused.
- **D-W14-39**, **D-W14-42**, **D-W14-34**, **D-W14-20**. The resume function already skips another owner's rows, drops a hold older than 72 h or past the 48 h window without sending, reuses the saved token as the mutation id and idempotency key, and treats an already-queued `workout.feedback` row as sent. This task only changes *when* it is called.
- Do not edit `rpeRating.ts` unless a tiny export is required for the hook (it should not be). Z14-42 owns the window-closed copy in that file.

## Gap list
Written against `main` at `ddd48f22`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).
- `resumeHeldWorkoutFeedback` is only called from `WorkoutTab`. `TraineeShell` does not resume on mount or when the app returns to the foreground.

## Acceptance criteria
- [ ] When `TraineeShell` mounts for a signed-in trainee, it calls `resumeHeldWorkoutFeedback` with this owner's id, the sync engine and the API (the same arguments Workout tab uses today). It also calls it when the app moves from background to active (`AppState`). A trainee who never opens the Workout tab still has a held rating and note sent, as long as they are inside the 48 h window.
- [ ] The 48 h edit window, the 72 h drop, owner checks, token reuse, "already queued" and in-process hold guards stay exactly as Z14-37 left them. A hold past the window is dropped without sending and without a new error banner on a screen the trainee is not looking at (resume already logs a refusal and is silent in the UI).
- [ ] Calling resume from the shell and from Workout tab in the same session must not send twice. The existing in-process and outbox guards should already prevent that; add a test that mounts both (or calls resume twice) and asserts one outbox row / one API call.
- [ ] Sheet drafts are not sent at launch. They still restore when their sheet opens.
- [ ] Store or resume failures never block the first screen (catch and `reportError`, as Workout tab does).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Decide-and-note
1. **Where to call resume (recommended):** `TraineeShell` on mount and on `AppState` `"active"`, not `App.tsx`. The shell is the first trainee screen; intake / waiting-review have no workout to resume. Say so if you have to put a hook in a shared place.
2. **Leave the Workout tab call (recommended):** keep it as a safety net for a tab remount; rely on the existing guards against a double send.
