## Outcome
On trainer web Clients (Ended), the "Ended Wed 21 Oct" chip and the Coached range ("Mon 3 Aug – Wed 21 Oct") show civil dates in the trainer's timezone. A relationship that ended at 23:30 IST on 21 Oct reads 21 Oct, not 21 Oct UTC's neighbour.

## Context
- W9 report (Z9-15/16 decision and follow-up): both use `startedAt.slice(0, 10)` / `endedAt.slice(0, 10)` on ISO instants in `ClientRow.tsx` (~l.72–82), i.e. UTC civil dates; moving both to the trainer's timezone was left as a follow-up. FitBud UI, 11 Nov 2026 (W10 launch brief).
- The web has no trainer-timezone source of its own; the API does (`domain/directory.ts` already loads the trainer's `users.timezone`, ~l.61 and ~l.240). Recommended approach (planner): the API adds optional civil dates `startedOn` and `endedOn` (`localDateSchema`, trainer zone, via the `packages/core` zone helpers) to `clientDirectoryItemSchema`, keeping `startedAt` / `endedAt` unchanged for other consumers; `ClientRow.tsx` formats `startedOn` / `endedOn` with `formatCivilDate`, falling back to the current behaviour only if the new fields are absent.
- Additive, optional contract fields: no migration, no breaking change. Mobile `clients.ts` (Z10-8, clients lane) is not touched here; it can adopt the fields later.
- `clients-directory.test.ts` exists from Z9-15; add cases, don't weaken existing ones. If it lives elsewhere, use the existing directory API test file and note it.
