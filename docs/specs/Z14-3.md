## Outcome
Trainer screens paint at once from the last answer and refresh underneath; switching tabs never shows a skeleton again; the client page loads in one round; the first screen after a cold start is not held up by push setup.

## Context
- Diagnosis #1 (FitBud Tech cause 4). D-W14-6 (trainer online-first with instant paint). Z14-1 makes the server side fast; this task removes the app's own waits. Independent of Z14-1, but measure after it merges if it has.
- Trainer writes stay online with optimistic UI and Undo; no outbox (D-W14-6).

## Gap list
- `TrainerShell.tsx:350-401` renders only the active tab; each switch remounts and refetches behind a skeleton.
- `ClientsTab.tsx:352-357` calls `listClients` twice plus attention groups and coach asks on every load.
- `ClientStatusScreen.tsx:165` then `:183`: two sequential rounds for a client's page.
- `AuthProvider.tsx:393-397`: relationships, then push registration, awaited before the first screen.
- `trainer/cache.ts` keeps snapshots in memory only.
- Written against `main` at `2c9819d3`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] Visited trainer tabs stay mounted; switching back shows the last data instantly and refreshes in the background if older than 30 s; pull to refresh still forces a reload.
- [ ] Needs you, Clients, Check-ins and the client page paint from the last snapshot (memory, and the device store via the same `AsyncKeyValue` once Z14-5 has merged; memory-only before that is acceptable, record it), with a subtle "Updating…" state, never a full skeleton when a snapshot exists. Snapshots are owner-scoped and cleared on sign-out and role switch (existing `setTrainerCacheOwner`).
- [ ] Clients tab makes one clients call (plus asks only if shown) and does not wait on the attention call (use Z14-1's counts on the clients list if merged; otherwise run attention in the background and fill badges when it answers).
- [ ] Client page loads its data in one parallel round.
- [ ] Cold start: push registration runs after the first screen renders (fire-and-forget with `reportError`), relationships and profile in parallel where independent; the existing cold-start offline and role-choice tests pass.
- [ ] Before/after timings (Expo web against the local seeded API with 80 ms injected latency) for Needs you, Clients, a client's page and a tab switch in `docs/qa/Z14-3/timings.md`.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
