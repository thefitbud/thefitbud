## Outcome
A trainer can run a client's assigned workout live (start, set complete/skip, complete) or submit a finished workout in one call, and the result is marked coach-logged.

## Context
- In-person coaching, added to the beta by Firoz on 4 Nov 2026 (PLAN-v2 D-P2-15). Default rules R1–R3 (recommended, Firoz can override): R1 a trainer-started workout is read-only to the trainee, who sees "Logged by your coach"; R2 trainers are exempt from Z6-11 log-time limits for the log-workout form, backdate cap 7 days; R3 a coach-logged workout counts once toward adherence and streaks, keyed by the workout execution id, never double-counted.
- Written against `main` at c398f67. The implementer re-checks each item against the latest `main` before building (AGENTS.md).
- Today `POST /workouts/assignments/:id/start`, `/executions/:id/sets/:setId/complete|skip` and `/executions/:id/complete` are `requireRole("trainee")` and check `relationship.traineeUserId === actor.userId`. Allow role `trainer` when `canAccessRelationship(actor, row)` and the relationship is active (ended clients stay read-only); set `logged_by_role=coach`, `logged_by_user_id`, `log_mode=live`.
- New `POST /workouts/assignments/:id/log` (idempotency key): whole workout in one body (exercises, sets with reps and `load_kg` or Bodyweight, optional session RPE, `performedAt`), creates a completed execution with `log_mode=form`.
- R1: trainee writes to a `coach` execution return `409 coach_logged_read_only`; trainee reads include `loggedByRole`.
- R2: trainer form logs skip Z6-11 bounds but `performedAt` must be ≥ now − 7 days and ≤ now (`422 backdate_limit`).
- R3: adherence and streak inputs read executions by execution id, so a coach-logged execution counts once; a trainee cannot start a second execution on the same assignment (existing unique index).
- Several open executions for different clients by the same trainer at once are allowed (parallel live logging, Z10-17).
- Trimmed from W14 Z14-5 (coach-logged sets, Undo) minus sessions and presence checks; Undo is the existing set skip / edit.

## Acceptance criteria
- [ ] Trainer can start, log sets, and complete a workout for an active client; the execution is `coach`/`live`.
- [ ] Trainer form log creates one completed `coach`/`form` execution; backdate over 7 days or in the future returns `422 backdate_limit`.
- [ ] Trainee writes on a coach-logged execution return `409 coach_logged_read_only`; trainee reads show `loggedByRole`.
- [ ] Another trainer's client or an ended client returns `403`/`409` as today.
- [ ] Adherence counts a coach-logged workout once (test with a retried idempotent form log).
- [ ] Contract, client method, route and authz tests; `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Out of scope

- Product rules (CLAUDE.md, never break): only the trainer resolves an exception (no auto-resolve); no auto-send (WhatsApp is a wa.me prefill); no percentages or streaks; payments are tracking only; ended clients are read-only on server and UI.
