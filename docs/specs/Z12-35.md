## Outcome
Any mobile PR can dispatch one workflow that builds its head as a native app on the iOS simulator and the Android emulator, runs its Maestro flows against a locally seeded API in light and dark, and fails on any crash, red box or warning, with screenshots named by screen ID.

## Context
- W12-PROMPT Z12-35 and §3; D-W12-16 (GitHub Actions: `macos-15` standard runner for iOS, `ubuntu-latest` + `reactivecircus/android-emulator-runner` for Android; API seeded and run **on the runner**, never staging; not a required check; `qa.yml` untouched).
- Reuse what exists: `scripts/qa/build-ios-sim.sh`, `build-android-apk.sh`, `android-emulator-prep.sh`, `run-maestro.sh`, `run-maestro-ios.sh`, `sign-ios-simulator-app.sh` (they target staging; the device workflow points them at the local API).
- The run does not print, log or upload credentials; demo passwords come from the existing env vars.

## Gap list
- No device workflow: `.github/workflows/` has `ci.yml`, `design-review.yml`, `qa.yml` (staging only).
- No `scripts/qa/device/`.
- `assert-no-crash.yaml` lacks "Requiring unknown module", "Encountered two children", "Each child in a list", "VirtualizedLists should never be nested", "Possible unhandled promise".
- No vitest setup fails on `console.error` (`apps/mobile/vitest.config.ts` setupFiles is `src/test/render.tsx` only; `apps/api/src/test-support/vitest-setup.ts` has no console check).
- Written against `main` at `3c227e12b`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] `device.yml` (`workflow_dispatch`, input `ref` and flow tags) builds the given ref, boots the API with `pnpm db:reset` (or `db:reseed` once Z12-34 lands) on the runner, and runs on iOS (latest Xcode and iOS on `macos-15`) and Android (latest stable API image).
- [ ] Scripts: theme switch (`xcrun simctl ui booted appearance light|dark`; `adb shell cmd uimode night yes|no`); offline/online (Android `adb shell cmd connectivity airplane-mode enable|disable`; iOS: stop the API or block its host, recorded which); push (`xcrun simctl push` with the app's payloads; FCM test payload or `adb` broadcast on Android); lock-screen taps (XCUITest springboard or `idb ui tap` on iOS, UiAutomator on Android).
- [ ] Screenshots named `<screen ID>-<theme>-<platform>.png` into `docs/qa/W12/shots/` (uploaded as an artifact; tasks commit theirs).
- [ ] Device logs collected (`xcrun simctl spawn booted log stream --predicate` for the app; `adb logcat`); the run fails on any crash, red box, LogBox error or warning, `console.error` or `console.warn`. Nothing is allow-listed without a written reason in the PR.
- [ ] `assert-no-crash.yaml` extended with the five strings above.
- [ ] Console-error vitest setup in every vitest workspace (D-W12-28); `pnpm test` green.
- [ ] A generator rebuilds `docs/qa/W12/parity.md` rows from `screen-profile.md` and keeps every verdict already written.
- [ ] The harness runs on `main`; an example run on the current app is linked in the PR (failures expected), including Z12-33's two-trainer check (D-W12-31).
- [ ] `docs/runbooks/device-gate.md`: how a task dispatches the gate and reads the result.

## Out of scope
- Product rules (AGENTS.md, never break): only the trainer resolves an exception; no auto-send (WhatsApp is a wa.me prefill the user sends); no percentages or streaks; dates read like "Wed 21 Oct", never ISO or raw enums; payments are tracking only; ended clients are read-only on server and UI.
- Working rules: no remote or deploy commands; no secrets (demo passwords only from the existing env vars); one branch `claude/<ID>-<slug>`, one PR `<ID>: <summary>` off the latest `main`, updated by merging `main`; never cancel an Actions run; never write the mention handle.

## Tests to add

- The console-error setup has a test proving a `console.error` fails a test.

## Stop conditions
- The workflow would need a new secret, a repo-settings change or a required-check change: ask in the PR and park it (prompt §1).
- A mock, frame or decision this spec needs is missing, or still **Open** in `docs/specs/batches/W12.md`.
- A file outside `files_owned` must change, or a shared file is needed before its earlier holder has merged (D-W12-20).
- A destructive or irreversible data change, a rewrite of coaching history, or a change to published-plan immutability that this spec does not state.
- A remote or deploy command, a production credential or production data would be needed.
- Everything else: take the recommended option, record it in the PR and for the report (AGENTS.md "Decide and note").
