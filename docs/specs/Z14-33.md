## Outcome
In the trainer app, tapping a client's **name** (not only the picture) in an Activity or Check-ins row opens their profile; Activity rows for a client's meal edit or removal look like TM-09e (unread dot, pencil and bin tags, "ate out" on a removal); the Activity client picker searches **all** clients; and the client page's onboarding text uses the first name instead of guessing He or She.

## Acceptance criteria
- [ ] **Activity rows:** tapping the client's first name opens that client's profile (pushed, Back returns, scroll kept, as the avatar does); tapping the rest of the sentence or the tag row opens the event as today. No interactive element is nested inside another on web (the row keeps the avatar and the name link as siblings of the event button, like Check-ins does). Match TM-09e at 393 and 360 wide and at 120% text; if the name cannot sit inline in the sentence without nesting, put the name as its own bold first line and the sentence under it, and note the deviation.
- [ ] **Check-ins rows:** the name line is a `ClientNameLink` sibling above the row body; tapping it opens the profile; the rest of the row opens the review (To review and Reviewed) or nothing (Overdue) exactly as today.
- [ ] Not a link inside the client's own pages, the client picker, or pickers (D-W14-27(a) as written).
- [ ] **TM-09e:** an "Edited" row shows a pencil icon in its neutral tag and a "Removed" row a bin icon; both rows show a small dot at the right while unread. The removal sentence ends "· was 1,120 kcal, ate out" when the removed meal was an ate-out (via `mealRemovedActivityLine(..., previousAteOut)`).
- [ ] **API (additive):** each `client_edited`/`client_removed` event for a meal carries `unread: boolean` (true when the trainer's `trainer_client_log_edited` inbox row for that entry is unread), `notificationId` (that inbox row's id, only while unread) and `previousAteOut: boolean` (the removed or replaced entry's previous deviation kind was `restaurant`). Both optional in the schema, never on other event types. The unread lookup adds **at most one** D1 statement, batched with an existing read, flat in the page size (extend the feed's query-count test or add one). Opening the event (the meal sheet) marks that inbox row read through the existing `POST /notifications/:notificationId/read` (using `notificationId`) and clears the dot at once; no new endpoint.
- [ ] **Client picker:** typing in the picker searches the server (`listClients({ q, limit })`, debounced about 250 ms, first page) so any client is found; with an empty query it shows the loaded clients as today. A search failure shows a plain "Couldn't search just now. Try again." line with the loaded clients still usable; offline searches only the loaded clients and says so. Selection, Clear and the "N clients" behaviour are unchanged.
- [ ] **Onboarding words:** `onboardingWaitingCopy` and its caller use the first name only: "{First} accepted your invite 2 days ago but hasn't sent the intake form, so you can't plan yet." and "Review {First}'s answers on FitBud web, then assign a plan." No `possessive`/`subject` inputs remain; no `gender` read in this path.
- [ ] `usePagedList`: a new test with overlapping pages proves a row is not shown twice and order is stable; if it fails on `main`, fix `usePagedList.ts` (de-dupe by id) and say so.
- [ ] New flow `F32-client-profile-from-name.yaml` (tags `device`, `trainer`, `z14-33`): Clients → Activity → tap a client's name → profile opens → Back returns to Activity; same from Check-ins. Selectors by `testID` (`client-name-link`, `client-avatar-link`, `client-status`); passes the Z14-29 guard.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Decide-and-note
1. **Name placement (recommended):** inline in the sentence if it can be done without nesting buttons on web; otherwise name on its own line (see the first acceptance item).
2. **Mark read on open (recommended):** opening the Activity event marks the matching inbox row read; if the entry is gone, leave the dot cleared locally only.
3. **Picker search (recommended):** server search by `q`, first page only; no paging inside the picker.
