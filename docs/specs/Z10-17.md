## Outcome
In one in-person session the trainer adds several clients, each with their own started workout, and switches between them to log sets without losing anyone's progress.

## Context
- In-person coaching, added to the beta by Firoz on 4 Nov 2026 (PLAN-v2 D-P2-15). Default rules R1–R3 (recommended, Firoz can override): R1 a trainer-started workout is read-only to the trainee, who sees "Logged by your coach"; R2 trainers are exempt from Z6-11 log-time limits for the log-workout form, backdate cap 7 days; R3 a coach-logged workout counts once toward adherence and streaks, keyed by the workout execution id, never double-counted.
- Written against `main` at c398f67. The implementer re-checks each item against the latest `main` before building (AGENTS.md).
- "Add client" from the live screen starts another execution (Z6-19 allows several open executions per trainer). Client switcher (chips) shows each client's current exercise and set.
- State per execution, persisted locally so an app restart resumes all; offline queue keyed by execution id.
- Trimmed from W14 Z14-14 (group logging) without roll call; same-exercise bulk entry is out of scope.
- Design guide for every UI task: `docs/design/README.md`, `docs/design/DESIGN-NOTES.md`, `docs/design/DECISIONS-21OCT.md`. Dates read like "Wed 21 Oct" (never ISO), enums through `labelFor`, touch targets ≥ 44 pt / 44 px, tabular numbers.
- Design-review: until Z11-1 is on `main` (PLAN-v2 D-P2-7) the reviewer compares captures with frames side by side and the PR says "design-review tool not on main yet".

## Acceptance criteria
- [ ] Trainer runs 3 clients' workouts at once, switches freely, and each finishes as its own `coach`/`live` workout.
- [ ] Killing and reopening the app restores all open workouts.
- [ ] No set is written to the wrong client (test per execution id).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass; captures matched against DS8 frames.

## Out of scope
- Sessions, attendance, roll call, calendar, agenda, reminders (Phase 10, W14, post-beta; PLAN-v2 D-P2-15).
- Product rules (CLAUDE.md, never break): only the trainer resolves an exception (no auto-resolve); no auto-send (WhatsApp is a wa.me prefill); no percentages or streaks; payments are tracking only; ended clients are read-only on server and UI.
- Working rules (CLAUDE.md): never run remote or deploy commands; no secrets in code, logs or commits (only `.example` env files and the demo seed); one task, one branch `claude/<ID>-<slug>`, one PR `<ID>: <summary>` off the latest `main`; update by merging `main`, never rebase or force-push.
