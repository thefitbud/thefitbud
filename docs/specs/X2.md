## Outcome
A phone dev build talks to the API URL it was built with, and `pnpm dev` works from each app without the "No projects matched the filters" failure.

## Context
- The three fixes (beta task list v14, X2, from v13):
  1. Read `process.env.EXPO_PUBLIC_API_BASE_URL` **literally** in `apps/mobile/src/lib/api.ts`, so Expo's Babel transform inlines it at build time. Expo only inlines the literal member expression `process.env.EXPO_PUBLIC_…`; a dynamic lookup through `globalThis.process?.env` is not inlined and is `undefined` in a release/dev-client bundle.
  2. `predev` filter: `pnpm --filter thefitbud build:packages` → `pnpm -w run build:packages`. CI shows "No projects matched the filters" (the root package is named `thefitbud`, but `--filter` from inside an app does not match it). In W1, X2 fixes `apps/mobile/package.json` and `apps/trainer-web/package.json`; the same fix in `apps/api/package.json` is done by I4c (W1.md ownership fix, 31 Oct 2026).
  3. Pin `react-native-svg` to the Expo SDK 52 version, **15.8.0** (what `npx expo install react-native-svg` selects for SDK 52).
- Decision D-B5 / D-W1-1 (Firoz, 30 Oct 2026): X2 does not wait for F4d (post-beta diet UI fix).
- Lockfile rule (W1.md): AU1 adds `jose`; X2 changes `react-native-svg`. Whichever merges second merges `main` and re-runs `pnpm install`.
