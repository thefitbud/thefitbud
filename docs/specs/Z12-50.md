## Outcome
A coach's nudge is always a FitBud push with the fixed title "{Coach first name} nudged you" and an editable body; it is capped at 2 per client per day; clients with push off or reminders paused get it in their in-app inbox only, and the coach sees which.

## Server rule as built (server PR, 14 Nov 2026)
Z12-50 ships as two PRs (orchestrator): this server + contracts PR, then the mobile sheet and web alignment after Z12-47. The route's OpenAPI description carries the same rule.

- **Request** `POST /notifications/relationships/:id/nudges`: `activityType`, `activityId`, optional `body` (trimmed, 1–200 characters; empty or too long → 400 `INVALID_REQUEST`; a link → 400 `NUDGE_BODY_HAS_LINK` "Nudges can't include links."). Links are a scheme (`https://`, `mailto:`, `tel:` …), `www.`, or a bare domain on a common top-level domain (`wa.me/…`, `bit.ly/…`, `example.com`). Absent `body` → the Gentle template for the activity type: workout "Your workout is waiting. Can you fit it in soon?", meal "This meal wasn't logged. Can you add it, even roughly?", check-in "Your check-in is waiting. Can you send it when you get a moment?". They are generic on purpose (no item, day or time the server would have to invent); the sheet composes the item-specific Gentle text and always sends `body`.
- **Title** "{Coach first name} nudged you": first word of the coach's `trainer_profiles.display_name`, "Your coach nudged you" when it is empty; never from the request. Title and body are stored on the notification row (`payload_json`, no migration), sent as the push's display text (the push `data` stays the routing payload), and returned on the notification as `title` and `body` by `GET /notifications`, the read endpoint and the nudge response, so the trainee's push and inbox row read the same text.
- **Response** adds `nudgedAt` (the returned nudge's send time), `delivery: "push" | "inbox"` and `inboxReason: "push_off" | "reminders_paused" | null`; quiet hours keep the existing `deferredForQuietHours` + `quietHoursEnd` (held is a flag on a `push` delivery, not a third value).
- **Delivery:** reminders paused (`reminder_states.mode = paused`, not expired) → inbox only, `reminders_paused` (no longer 409 `REMINDERS_PAUSED`). `notification_preferences.push_enabled = false`, or no active device token (the app unregisters its token when the OS permission is off; there is no separate OS-permission column) → inbox only, `push_off`. Inbox-only rows are `delivered` with no delivery attempt. Otherwise a push; inside the client's quiet hours the row is `deferred` (in the inbox at once) and the cron releases the push when they end. A held push re-checks push off / paused at release and stays inbox-only (`delivered`) if either now applies. Reminder categories (workout/meal/check-in reminders) do not gate a nudge: it is the coach's message, not an automatic reminder.
- **Limits:** 2 nudges per client (relationship) per client civil day, the day taken in the trainee's stored `users.timezone` (default "UTC") through core `formatLocalDate` / `localDateTimeToUtcIso`, counted over every `activity_nudge` row created that day whatever its state → 429 `NUDGE_LIMIT` "You can nudge this client again tomorrow." with `retryAfter` = seconds to the client's next midnight. The per-item 4 h cooldown is gone. The trainer-wide hourly limit (3) stays, now as 429 `NUDGE_RATE_LIMITED` "You can nudge again in N min", so the sheet can tell it from the daily cap. One nudge per item per client day (existing dedupe key): a repeat returns the stored nudge with `deduped: true` and does not count again, which is also what makes a retried request safe (the route takes no idempotency key). `deduped: true` (still 200) means "already nudged about this item today; the new body was not sent": the response carries the stored `notification.body` and `nudgedAt` (the original send time) so the sheet can render TM-04n. Ended relationships stay 409 `RELATIONSHIP_ENDED`; another trainer's relationship stays 404.
- **Decisions taken (decide and note):** inbox-only state `delivered`, not `suppressed` (clients read `suppressed` as "Already logged"); categories do not gate nudges; generic Gentle defaults; held = flag; the push display text needed a small additive option in `apps/api/src/lib/expo-push.ts` and `lib/push-provider.ts` (outside `files_owned`, recorded for the orchestrator).
