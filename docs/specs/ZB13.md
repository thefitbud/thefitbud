## Outcome
Production and staging data is exported to R2 every night and kept for 30 days, and a documented, tested restore proves the exports are usable.

## Context
- Covers master-list (v13) items BP2. Everything the implementer needs from those rows is pasted here.
- Before public release; complements D1 Time Travel (30 days on paid plans).
- Shape: a separate Worker `apps/backup` (Cron Trigger 02:30 IST = 21:00 UTC) that calls the D1 export REST API for the env's database, polls until done, and streams the SQL dump into the R2 bucket `fitbud-backups-<env>` at `d1/<YYYY-MM-DD>.sql`; a lifecycle rule (set by Firoz) expires objects after 30 days.
- Needs a Cloudflare API token with D1 export permission as Worker secret `CF_D1_EXPORT_TOKEN` (name only; Firoz creates it, Q-W6-1). The account id and database id come from `wrangler.toml` vars, not secrets.
- Restore test: `pnpm --filter @fitbud/backup restore-test <file>` imports a dump into a local D1 (`wrangler d1 execute --local`) and checks table counts against the dump; run in CI on a fixture dump only.
- The workspace file gets one entry (`apps/backup`) — ZA10 (W5) owned it last; no W6 lane touches it.
