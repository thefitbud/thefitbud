## Decide-and-note
1. **Counsel status (D-W14-31, recommended).** Put the draft text on the pages, and keep the "pending counsel review — not yet in force" banner until Firoz records sign-off or asks to drop it. Do not describe the text as approved or in force.
2. **How to copy (recommended).** From `origin/claude/legal-drafts-v2`, copy drafts 01–08 into `docs/legal/published/` (or an equivalent folder the app bundles). Substitute placeholders from `packages/core/src/legal-config.ts`. Before publishing a page, delete `> **COUNSEL:**` and `> **FACT:**` callouts (the drafts say these come out before publication) and do not leave `[[…]]` markers in production. Do not rewrite the legal prose. Do not copy counsel-only files onto `main`.
3. **Placeholders (recommended, simplest gate).** One `legal-config.ts` holds every substitutable value. Already filled in #177 (copy from the drafts or FILL-SHEET, do not invent, do not repeat the address in other files): contracting party, registered address, grievance officer, effective date (1 December 2026), support / legal email (`tech@thefitbud.com`, already used on `main`). Still open — leave `null` / unfilled, render as "To be confirmed" on staging, and **do not invent a value**: liability-cap floor (draft proposes ₹5,000, counsel to confirm); notice period (30 days is suggested); age above which medical clearance is specifically urged (40 is common); every retention period in draft 09 / Privacy §9; production data location (Cloudflare D1 primary region and R2 bucket location — a fact from the dashboard, not a guess); every `[[CONFIRM: …]]` statutory period; the open-source licence list for fonts and icons in draft 08; Apple minimum end-user terms remain as in draft 01 §19. Mechanism: a helper `assertLegalPublishable()` that throws if any required value is unfilled. Call it from the **production** trainer-web / API build or deploy script (the production wrangler / Vite production path). Unit tests cover both sides: staging/dev renders the marker and stays green when values are missing; a test that sets the production flag fails if any value is unfilled (and a mutation that empties a required value fails that test). Do not add a banned-strings rule that would fail ordinary CI or staging builds.
4. **Mobile opening (recommended).** A JS `LegalDocumentScreen` that renders the same published markdown, pushed from More, sign-in and invite-accept, so no new native module and no extra EAS build. 44pt back control. Optional "Open in browser" uses `legalUrl`. If the shared back components from Z14-18/Z14-25 are not on `main` yet, use the existing screen header pattern and note it.
5. **Credits (recommended).** Keep the factual exercise / food credits already on `/credits`. Add any extra notices from draft 08 that do not contradict those facts. If the font and icon licence list is still `[[TO BE COMPLETED]]`, leave it as "To be confirmed" (or generate it from the manifests if that is straightforward and accurate — do not guess).
6. **New routes (recommended).** Use the paths in the table above, all public. `/terms` stays the master Terms of Service; trainer and trainee terms are their own paths and are linked from it and from the nav.
