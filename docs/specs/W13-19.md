## Outcome
Templates and the check-in builder match the design system's button rules and have no duplicate controls.

## Decision: "Use for client" (D-W13-25)
The design system names the row action's style: *Quiet (`--fill`, row actions: Use for client, Review, Open)* (`DESIGN-SYSTEM-v3-web.md` §5.1; frame W-168 draws a filled grey button). The build uses `variant="secondary"` (white, outlined) at `TemplatesHub.tsx:~901`; every other row action (Review on Overview and Home, Remind on Activity) is Quiet, so the outlined button is the odd one out (`qa-captures/w13-5/W-168-templates-1440x900.png`). It does not match; make it Quiet.

## Problem
1. "Use for client" outlined instead of Quiet (above).
2. Use-for-client client picker: the option rows have an uneven gap between the name and "· Ready to coach" (selected row "Ananya Bose · Ready to coach" against "Deepak Nair  · Ready to coach"; `qa-captures/w13-5/W-174-use-for-client-modal-1440x900.png`). Make the separator spacing identical in every row.
3. Check-in builder, selected question panel: **Answer type** is a four-way segment (Number, Scale 1–5, Text, Photos) and right under it a second control labelled **Type** repeats "Scale 1–5" with the hint "Yes / no and choices are only in this list." (`qa-captures/w13-4/W-171-1440x900.png`, `W-171-1024x1366.png`). Frame W-171 has one control. Remove the duplicate; if the second control is the only way to reach Yes/no or Choice answer types for the trainer's own questions, keep it but label it as the one that decides and make the segment follow it, so there is a single source (record which in the PR).
4. **Save version is still shown below 1024**, where the builder is read-only (D-W13-24). Hide it (and any other editing control) below 1024.
