## Outcome
The Clients list toolbar is one row, as drawn in frames 136 and 140: search, four filter dropdowns, and the Current/Ended segmented switch at the right end. The table's Action column is fully visible at 1440, 1280 and 1024 px.

## Context
- Added 10 Nov 2026 from the W7 report follow-ups ("Frame 136 filters" and "Clients table Action column clips at 1280 and 1024"). Decision **D-W8-13** (Firoz, 10 Nov 2026): the filters are dropdowns, not rows of inline pills; the Current/Ended switch is a segmented switch at the right end of the same toolbar row, not a separate row.
- **Toolbar as drawn (frames 136 and 140, 1440x900):**
  - Above the toolbar: page title "Clients", the subtitle "{n} clients · {m} active" (built today as only "{m} active" / "{n} ended"; fix it, see Gap list) and the primary "+ Add client" button at the top right (built; keep).
  - **One toolbar row**, left to right: a search field (magnifier icon, placeholder "Search clients", about 280 px wide at 1440, white, 1px border, rounded); then four dropdown buttons in this order: **Status**, **Adherence**, **Goal**, **Renewal**. Each is a white, outlined, fully rounded button with the label and a chevron-down, same height as the search field. There is no "More" button and no inline pill row.
  - **Right end of the same row:** a segmented switch on a grey track with two segments, "Current {count}" and "Ended {count}"; the selected segment is white with dark text, the other is grey text on the track.
  - Frame 140 (Ended): the same toolbar, with "Ended" selected.
- **Open dropdown state is not drawn.** Build it as an accessible menu or listbox anchored under its button that lists the same options (and facet counts) the current pills show, with the same URL parameters and history behaviour (push on change, Back restores; TW-06). A selected filter is shown on the closed button in text (for example "Status: Invited"), never by colour alone, and there is a way to clear it. Keyboard: Enter/Space opens, arrows move, Escape closes and returns focus. Record the exact choice in the PR (decide and note).
- **Table (unchanged columns, fix the clip):** current — Client (avatar, name, goal subtitle), Status, Adherence, Next check-in, Plan, Renewal and an unlabelled Action column (Open / Review intake / Set up plan / Resend invite); ended — Client, Status ("Ended Sat 3 Oct"), Coached ("Mon 6 Jul — Sat 3 Oct"), Last plan, Reactivate, and the footer line "Ended clients are read-only. Their history and progress stay visible."
- **Action column clip (W7 report):** in `clients.css` the `nowrap` client name and subtitle (~l.409) and `.roster-plan` (~l.470) size the auto-layout table; nothing caps them and 16 px horizontal padding on 7 cells (~l.799) needs at least 1055 px against 974 px at 1280, so `.clients-table-wrap { overflow-x: auto }` hides Action (it reads "Op"). Fix: cap the Client and Plan columns with ellipsis (full text in a `title`) or use `table-layout: fixed`, and tighten the padding. Action must never clip at 1024, 1280 or 1440.
- `clients.css` is global and also styles add-client, welcome, review and other pages: change only the Clients-list selectors.
- **Shared e2e:** `tw-b-flows.spec.ts` test "roster search, Ended segment, FilterBar unclipped at 1280/1440" drives the pills and the "More" button and must be rewritten for the dropdowns. Change only that test; the W7 report also says its unclipped check passes on broken CSS, so make it wait for the counts to load and assert that the Action column cell is fully inside the table at 1280 and 1024.
- Design guide for every UI task: `docs/design/README.md` (v3 rules and the frame index), `docs/design/DESIGN-NOTES.md` (palette, type, spacing, components, data and time), `docs/design/DECISIONS-21OCT.md`, and the screen spec in `docs/spec/`. Dates read like "Wed 21 Oct" (never ISO), enums always go through `labelFor` (`packages/core/src/labels.ts`), touch targets are at least 44 pt / 44 px, counts use tabular numbers.
- Design-review step (W11 Z11-1): **Z11-1 is not on `main` yet**, so skip the script.
