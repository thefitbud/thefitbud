## Outcome
Every `Field` input is announced with its label by VoiceOver/TalkBack, and QT3's sign-in-by-code flow taps the code field by its label instead of the unverified `below:` selector.

## Context
- Source: the W3 report's "Follow-ups raised on 3 Nov" (`docs/specs/batches/W3.md`, 3 Nov continuation) and QA1's "Follow-ups raised" (`docs/specs/batches/QA1.md`); W3b is approved by Firoz, 3 Nov 2026 (`docs/specs/batches/W3b.md`). (QT3b).
- `Field` renders the label as a sibling `Text`, so the `TextInput` has no accessible name; `apps/mobile/.maestro/common/sign-in-code.yaml:17-21` carries a `TODO(QT3b)` and taps `below: "6-digit code"`.
- Default `accessibilityLabel` to `label`; a caller's explicit `accessibilityLabel` (in `...inputProps`) still wins. No `testID` needed unless a label is not unique on a screen.
