## Outcome
Coach create/edit for workouts, meals and measurements writes the domain row, audit, and activity-feed event atomically so concurrent coach logs do not 500 and audit/feed cannot diverge.

## Context
- Z6-19 leftover (W6 report). This is **atomicity and integrity**, not the later "cannot log skip or close" feature. Live logging stays parked in W14.
- W8 Z8-15 and Z8-16 **depend on this landing** (D-W7-12 / D-P2-24).
- **Serial hand-over:** Z7-20 merges first and releases `workouts.ts` / `meals.ts` (same pattern as W6 forms lane). Merge `main` before starting; do not run in parallel with Z7-20.
- Written against `main` at 893af647.

## Gap list
- Coach log/edit paths are not one transaction; concurrent logs can 500; audit and feed can diverge.

## Acceptance criteria
- [ ] Create and edit each run in one DB transaction covering the entry, `log_edit_events`, and activity-feed write.
- [ ] Concurrent coach logs on the same relationship do not 500; conflicts return a stable domain code.
- [ ] A failed feed/audit write rolls back the entry (no orphan).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Out of scope
- Coach cannot log whole-workout skip / close in-progress (later). Live logging (W14). Trainer-web UI (Z8-15/Z8-16).

## Tests to add
- Concurrent create; transaction rollback when a dependent write fails; feed and audit present together.

## Stop conditions
- A decision needed is missing or **Open**.
- A file outside `files_owned` must change.
- Destructive rewrite of historical coaching records.
- Remote/deploy, secret, or production data required.
