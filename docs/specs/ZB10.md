## Outcome
From the side panel the trainer can resolve several of one client's missed-workout, missed-meal or missed-log exceptions in one action with one outcome and note, and undo it within 5 seconds.

## Context
- Covers master-list (v13) items SPB, D11 (locked). Everything the implementer needs from those rows is pasted here.
- D11 (locked): per client, coaching-configuration exceptions only; bulk only for compatible types (missed workout, missed meal, missed log). Rejects pain/safety, asks, renewals, and ended relationships. Mark reviewed stays the existing client-level call.
- `POST /exceptions/bulk/resolve` `{ relationshipId, exceptionIds[], outcome, note? }` → per-item result `{ id, status: resolved|skipped, reason? }`; one resolution row per exception (outcome, note, actor, time) via the same domain path as `POST /exceptions/:id/resolve` (`apps/api/src/routes/exceptions.ts:1013`). `POST /exceptions/bulk/undo` `{ bulkId }` within 5 s restores each item's prior status.
- Only the trainer resolves (product rule); the API never auto-resolves. Idempotent by `Idempotency-Key`.
- DS2 (frames, not yet drawn) is needed for the UI only (W7 ZC6); the API scope is locked by D11, so this task does not wait for DS2.
