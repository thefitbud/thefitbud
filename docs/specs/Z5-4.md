## Outcome
The W6 backend tasks can run in parallel lanes, each owning only its own module files, because the three shared index files are edited once, here.

## Context
- Covers master-list (v13) items (enabler for B1b, B2b, B2c, B3b, B4b, SPB, BP1). Everything the implementer needs from those rows is pasted here.
- `packages/contracts/src/index.ts` (791 lines), `packages/api-client/src/index.ts` (2452 lines, augment pattern: `installStage1ClientMethods` at the end, from `stage1-augment.ts`) and `apps/api/src/index.ts` (routes mounted at `:92-122`) are touched by every new endpoint. Editing them in parallel lanes causes conflicts, so this task adds every W6 module once, empty.
- Per module: `packages/contracts/src/<m>.ts` exporting nothing yet but a `// W6 <task>` header and an empty object type; `export * from "./<m>.js"` in the contracts index; `packages/api-client/src/<m>-augment.ts` with `install<M>ClientMethods(cls)` doing nothing, called from the client index after `installStage1ClientMethods`; a Hono router per route file that returns 404 `not_implemented` for every path, mounted at `/strength`, `/client-settings`, `/steps`, `/exceptions/bulk` (before `/exceptions`), `/account`. Also `apps/api/src/jobs/account-purge.ts` exporting `runAccountPurge(env, now)` that does nothing yet, called once from the `scheduled()` handler in `apps/api/src/index.ts`, so Z6-14 (W6) fills it in without touching the index (D-W6-8).
- Authorization matrix: W6 tasks put their auth cases in their own `<module>.authz.test.ts` instead of the shared `authorization-matrix.test.ts`.
