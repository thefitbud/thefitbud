## Outcome
The week strip shows an unlogged today as open (`due`), credits a started past day as `partial`, and keeps skips counting toward `done` (D-W6-10).

## Context
- Rules locked by FitBud UI on 6 Nov 2026 at Firoz's request (D-W6-10). Do not reopen.
- `deriveWeekDayFromWorkouts` in `apps/api/src/domain/week-read-model.ts` (BT9/CU23) is the only derivation and stays the only one.
- On `main` (504a662): unlogged today returns `partial` (line ~184); a past day with `started` and nothing closed returns `missed`; skipped is already in the done sets.
- `due` is derived from assignments + no observations + open window — never from the date alone (CU23).
- DateNavigator state, colour and a11y live in `packages/ui-mobile/src/DateNavigator.tsx` (BT13); `TraineeDateNavigator.tsx` is the trainee wrapper. Labels follow Z5-3 (no raw enum words).
- Overlap note: DateNavigator files were BT13; week-read-model was CU23/BT9. Z6-23 also edits `labels.ts` (different block) — run Z6-22 and Z6-23 one after the other, or merge `main` before the second PR.

## Rules (D-W6-10)
1. Today, planned work, nothing logged, window open → `due`.
2. Skipped counts as closed; all closed (completed/modified/skipped) → `done`. Item status stays `skipped`. Never auto-skip.
3. Past day with real progress (`started`, or any logged set/item) and not all closed → `partial`.
4. Past day, planned work, nothing logged → `missed`. Window closed with nothing logged → `missed`.
5. Today started-not-finished → `partial`. No planned work → `rest` (`future` if after today). Later assigned days → `future`.
