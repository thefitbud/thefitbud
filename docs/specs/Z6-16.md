## Outcome
A deleted account can be archived for 6 months and then purged, because the users table records when it was archived and when it will be purged.

## Context
- Covers master-list (v13) items BP1 (schema part, added 3 Nov for D-W6-7). Everything the implementer needs from those rows is pasted here.
- D-W6-7 (Firoz, 3 Nov): deleting an account archives it for 6 months; the user can reactivate it by signing in again; after 6 months it is purged.
- `users.account_state` gains the value `archived` (today `active`, `disabled`; `apps/api/src/db/schema.ts:18-20`). Add `archived_at TEXT NULL` and `purge_after TEXT NULL` (ISO UTC, same style as `created_at`), and an index on `purge_after` for the daily purge query.
- CHECK: `archived_at` and `purge_after` are both NULL unless `account_state = 'archived'`, and both set when it is.
- Migration number: the next free number when the task starts from `main` (expected after Z6-4). Remote application to staging and production is done after merge by the batch's coding agent or FitBud UI (manual list P2); the implementer runs migrations locally only.
