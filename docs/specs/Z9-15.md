## Outcome
Every item in the client list response carries the relationship's coaching start, so the Clients page can show "Coached Mon 9 Jul – Sat 3 Oct" for ended clients (Z9-16).

## Context
- Added 11 Nov 2026 from the W8 report follow-ups ("No start date in the client list API, so frame 140's Coached column is missing", Z8-19). FitBud UI brief approved by Firoz.
- `apps/api/src/domain/directory.ts` already reads `relationship.startedAt` (it feeds `week` via `coachingWeekNumber`, ~l.250) but does not return it. `endedAt` is already on the item (`packages/contracts/src/directory.ts` `clientDirectoryItemSchema.endedAt`, ~l.33).
- **Add `startedAt`** to `clientDirectoryItemSchema` with the **same type as `endedAt`** (`isoDateTimeSchema.nullable().optional()`, backward compatible) and return it from both item builders in `directory.ts` (the active and the pending/invited paths; invited rows with no relationship start return `null`) **and** from the final output mapping (~l.343–358), or it is dropped. The route in `clients.ts` passes it through unchanged (the response is parsed with the contract).
- **Civil dates and timezone (record in the PR):** the ended roster chip in `ClientRow.tsx` formats `endedAt.slice(0, 10)` with `formatCivilDate` (the UTC calendar date). Z9-16 formats `startedAt` the same way, so the Coached range and the ended chip always agree. Moving both to the trainer's timezone is a follow-up, not this task.
- **No migration.** No new query: `startedAt` is on the row already loaded.
- Existing list/directory tests: there is no `clients.test.ts`; coverage of `GET /clients` sits in broader suites (`iteration-a.test.ts`, `batch-0.test.ts`). Shared tests are add-only, so put the new cases in the new file `apps/api/src/routes/clients-directory.test.ts`, using the same persisted-fixture helpers those suites use (real relationships, no mocks of the domain).
- Re-check each gap item against the latest `main` before building (AGENTS.md).
