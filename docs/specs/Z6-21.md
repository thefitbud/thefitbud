## Outcome
A new trainee's first `GET /sync/pull` runs a small, bounded number of D1 queries, so Today fills in seconds, not minutes.

## Context
- Source: W5 report #262, Z5-7c. `GET /sync/pull` bootstraps a trainee's change log one row at a time in `apps/api/src/domain/sync.ts`: about **3,544** D1 queries on the first pull and about **107** on later pulls.
- Staging D1 is in SIN; new trainees see an empty Today for minutes, and the bootstrap may hit D1's per-request query limit. The old shared QA accounts passed only because api-smoke had already written a `change_log` row.
- Until this lands, trainee flows in device QA on the per-suite accounts (D-W5-14) stay red, and real beta trainees would hit the same bug. Do not hide this in QA flows.
- No migration expected. Different files from every other W6 lane, so it runs in parallel with Z6-1.

## Gap list
- `apps/api/src/domain/sync.ts`: bootstrap inserts/reads change-log rows per record; payload loads are per row (N+1).
- Written against `main` at 504a662. The implementer re-checks each item against the latest `main` before building (AGENTS.md).

## Acceptance criteria
- [ ] Bootstrap writes change-log rows in batches (D1 `batch()` / multi-row insert, chunked under D1 bound-parameter limits), not one statement per record.
- [ ] Payload loads are grouped per entity type (`IN (...)` chunks), not one query per row.
- [ ] First pull for a seeded trainee (demo-seed size or larger) runs a bounded number of queries that does not grow with record count (target ≤ ~50; state the measured number in the PR).
- [ ] Later pulls are no worse than today (≤ 107) and ideally lower.
- [ ] Pull response content (records, cursors, ordering, tombstones) is byte-for-byte equivalent to `main` for the same fixture.
- [ ] No new export from shared index files; if one is unavoidable, list it in the PR and stop.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.
