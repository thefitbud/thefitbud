## Outcome
Confirm, skip, and workout-start request schemas accept an optional client log time; the API judges bounds from that time when present so a submit just before midnight is not forced onto the server-receive day.

## Context
- Z6-11 hardening (W6 report). Those actions currently send no client log time, so offline/near-midnight entries can land on the receive day.
- **API/contract only** (D-W7-12). Mobile and web adoption stay with W9 / later UI tasks — do not silently change only one client. Keep fields optional so existing clients keep working.
- Reuse `assertLogTimeWithinBounds` / existing error codes and static messages (D-W3-12).
- Written against `main` at 893af647.

## Gap list
- Workout start / skip / meal confirm paths stamp server `now` without a client-supplied log time.
- Contracts for those operations lack an optional client log-time field.

## Acceptance criteria
- [ ] Optional client log time on the named operations; when present, bounds use it; when absent, behaviour matches today.
- [ ] Near-midnight fixture: client time before local midnight accepted against the client day; no silent day shift to server receive.
- [ ] No mobile/web app files changed.
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Out of scope
- Client adoption (W9+). Changing already-applied migrations.

## Tests to add
- Route tests for confirm, skip, and start with/without client log time; midnight boundary in a non-UTC zone.
