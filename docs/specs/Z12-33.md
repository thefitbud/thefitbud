## Outcome
A trainer list fetched while trainer A was signed in can never be written into, or read from, trainer B's cache on the same phone, even when it resolves after A signs out and B signs in.

## Context
- ISSUE-MAP "Other W12 items": the Z11-8 late-write privacy race (Z11-8 listed it as residual risk because the callers were not owned). First code PR of W12 (prompt §4).
- Z11-8 already scopes keys by owner (`setTrainerCacheOwner`, `cache.ts:23`, set in `applyMe`, `AuthProvider.tsx:271`) and clears on sign-out (`AuthProvider.tsx:123`).
- Design: an epoch (or owner token) captured when a fetch starts and passed to the write; the module drops a write whose token is not the current one. Changing the owner bumps the epoch and removes the previous owner's keys. The three call sites change only to capture and pass the token; no other caller change.
- Device timing: D-W12-31 (the two-trainer device check runs in Z12-35's example run).

## Gap list
- `writeTrainerCache(key, value)` (`cache.ts:52`) writes under whoever is the owner **at resolve time**: a fetch started under A that resolves after B signs in writes A's data under B's key.
- `setTrainerCacheOwner` (`cache.ts:23`) switches owner without removing the previous owner's keys; only `clearTrainerCache()` on sign-out does.
- Call sites write without a token: `AttentionTab.tsx:216`, `ClientsTab.tsx:181`, `ClientStatusScreen.tsx:172`.
- Written against `main` at `3c227e12b`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] A write carrying a token from before an owner change is dropped (memory map and web `localStorage`).
- [ ] Changing the owner from A to B (a different user id) removes A's keys from both stores; setting the same owner again keeps them.
- [ ] Ownership still comes only from the server `me` response; the token is never read from cached data.
- [ ] Offline Attention, Clients and client status still read A's own snapshot while A is signed in.
- [ ] Sign-out and refresh-refused paths still clear the cache (Z11-8 tests stay green).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass; fresh review PASS.
- [ ] Device check per D-W12-31: in Z12-35's example run, sign in as `rahul.coach`, sign out, sign in as `priya.coach` on the same simulator and emulator; nothing from Rahul's account shows (Attention, Clients, a client page), online and offline.

- Working rules: no remote or deploy commands; no secrets (demo passwords only from the existing env vars); one branch `claude/<ID>-<slug>`, one PR `<ID>: <summary>` off the latest `main`, updated by merging `main`; never cancel an Actions run; never write the mention handle.
