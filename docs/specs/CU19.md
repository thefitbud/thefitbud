## Outcome
Every nightly / dispatched QA run also builds the staging app for the iOS simulator on a free GitHub macOS runner, boots a pinned iPhone simulator set to `Asia/Kolkata`, and runs the same `apps/mobile/.maestro` flows, so the CU17 class of bug (Hermes-iOS-only crash) fails a job instead of reaching Firoz's phone. Approved by Firoz, 3 Nov 2026 (D-W3b-14). Not a required check, same as `android`.

## Context

No paid EAS, no Maestro Cloud (D-QA1-8 carried over); emulator/simulator flakiness is accepted.
- **Android job to mirror** (`.github/workflows/qa.yml`, `android:` ~line 540 on `main`): `needs: [changes, seed-reset, api-smoke, web-staging]`, the `always()` `if:` gate on `seed-reset` and `changes.outputs.suites`, `concurrency: qa-staging` (D-QA1-7, the per-job form CU4 #186 introduced), env `TURBO_TELEMETRY_DISABLED`, `QA_MAESTRO_TAG`, steps: checkout (`persist-credentials: false`), Node from `.nvmrc`, Corepack pnpm, pnpm-store cache, `pnpm install --frozen-lockfile`, `pnpm build:packages` (Metro resolves workspace packages from `dist`, so this must precede any bundle), the **"Require the QA secrets" guard** (`QA_TEST_OTP_CODE`, `FITBUD_QA_PASSWORD`; fork → notice + skip, same-repo missing → error), Maestro CLI install, then the allowlisted `qa-upload/` copy (junit, `*.png`, logs only — never Maestro debug output) and `upload-artifact` as `qa-raw-mobile`.
- **CU18 (#197, open)** adds config sections to `apps/mobile/.maestro/common/*.yaml` with a hardcoded `appId: com.thefitbud.mobile.staging`, and explains that a subflow's `appId` is never evaluated. iOS staging bundle id is also `com.thefitbud.mobile.staging` (`apps/mobile/app.config.js:20`), so the same flows target iOS unchanged.
- **CU17** (spec merged in #193; implementation PR not yet merged) fixes the `Asia/Kolkata` Hermes-iOS crash; this job's first green run is its CI proof.

## Build approach: local prebuild + xcodebuild on the runner (chosen)
| | EAS profile `ios.simulator: true` | `expo prebuild` + `xcodebuild` on macOS runner |
|---|---|---|
| Cost | Free plan has a small monthly build quota and a queue (https://expo.dev/pricing); a nightly run would eat it and starve the human dev builds (AB5) | free (public repo, standard runner) |
| Secrets | needs a new `EXPO_TOKEN` secret in CI | none new |
| Speed | queue wait + ~15–25 min + artifact download | ~20–35 min cold, less with Pods/DerivedData cache |
| Fidelity to the commit | builds the pushed commit on Expo's servers | builds exactly the checked-out tree, like `build-android-apk.sh` does for Android |
| Repo change | `apps/mobile/eas.json` | none in `apps/mobile` |
**Pick: local.** It matches the Android job (local Gradle, no EAS), costs nothing, needs no new secret, and leaves the EAS quota for the human dev builds. `build-ios-sim.sh`: `APP_VARIANT=staging` + the same `EXPO_PUBLIC_*` staging env as `eas.json` `preview`, `npx expo prebuild --platform ios --no-install` (CNG output is not committed), `pod install`, then `xcodebuild -workspace ios/*.xcworkspace -scheme <app> -configuration Release -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath qa-results/ios-build CODE_SIGNING_ALLOWED=NO`. **Release** so the JS bundle is embedded and Hermes compiled, as on a device; no Metro server needed. Cache `~/Library/Caches/CocoaPods` and `apps/mobile/ios/Pods` keyed on `pnpm-lock.yaml`. `eas.json` is not changed.

## The `ios` job
- `runs-on: macos-latest`, `timeout-minutes: 120`, `needs: [changes, seed-reset, api-smoke, web-staging, android]` (after `android`, so the two never write staging at once even though both hold `qa-staging`), same `if:` shape with a new suites value `ios` (`all` includes it); on `pull_request` it runs when `mobile == 'true'`, like `android`.
- `concurrency: { group: qa-staging, cancel-in-progress: false }`.
- Steps as Android up to the secrets guard, then: `xcode-select` to a pinned Xcode, `build-ios-sim.sh`, Maestro install, then **boot a pinned simulator**: `xcrun simctl create qa-iphone "iPhone 15" com.apple.CoreSimulator.SimRuntime.iOS-17-5` (pin device + runtime that the image ships; print `xcrun simctl list runtimes` and fail with a clear message naming the missing runtime if absent).
- **Zone Asia/Kolkata:** the simulator takes its time zone from the host, so set the runner's zone before boot: `sudo systemsetup -settimezone Asia/Kolkata` (and `export TZ=Asia/Kolkata`); set locale `en_IN` via `xcrun simctl spawn qa-iphone defaults write -g AppleLocale en_IN` / `AppleLanguages '(en-IN)'` then reboot the simulator. The step **asserts** it: read the zone back (`xcrun simctl spawn qa-iphone date +%Z` → `IST`) and fail loudly if not. Whether the host-zone inheritance holds on the current image is **to be verified by the implementer**; if not, stop and report.
- `run-maestro-ios.sh`: `xcrun simctl install`, `maestro --device <udid> test apps/mobile/.maestro --include-tags "$QA_MAESTRO_TAG" --format junit --output qa-results/ios/junit.xml`, `-e` for the two secrets (never printed), `xcrun simctl spawn booted log stream --predicate 'process == "<app>"'` to `qa-results/logs/ios-sim.log`; exit with Maestro's code.
- Collect/upload exactly like Android but to `qa-raw-ios`, allowlisting `qa-results/ios/junit.xml`, `*.png`, `logs/ios-sim.log`.
- **report job:** add `ios` to `needs`; `summarize.mjs` gains `ios` in `SUITES`, reads `<in>/ios/junit.xml`, and scans `ios-sim.log` for a RN red box / `RangeError` / Hermes fatal the same way it scans `logcat.log`, failing the `ios` suite on a crash even if flows passed. `--expect` default becomes `mobile,ios,web,api,unit` only when `ios` was requested, so a run without it reports `not-run`, never a silent pass.

## Flows needing platform branches
Use Maestro's `runFlow: { when: { platform: Android|iOS } }`; never fork whole flow files.
- `session-persists.yaml:45` and `flows/trainer/attention.yaml:46` `pressKey: back` — no hardware back on iOS. iOS branch: tap the screen's own back control / swipe from the left edge; `session-persists` step 3 ("Android back leaves the app") is Android-only and skipped on iOS with a comment.
- `launchApp: permissions: all: allow` (attention, checkin-review, notes-more, clients, progress, workout-log, settings) — Maestro supports this on iOS simulators, including notifications; no change, but if a system alert still appears, add an optional `tapOn: "Allow"` under an iOS `when`.
- `hideKeyboard` (`common/sign-in-code.yaml:23,44`, `trainee/checkin.yaml:71`) — unreliable on iOS; iOS branch taps a non-input label instead. `common/**` is CU18's and `checkin.yaml` is CU11's (#192), so these edits wait for both to merge.
- `trainer/notes-more.yaml:61-63` Notifications row — label only, platform-neutral; verify.
- `common/assert-no-crash.yaml` — its red-box patterns are RN-level and apply on iOS; the "Android view creation" pattern is harmless on iOS. Keep; the iOS log scan in `summarize.mjs` covers native crashes.
- Any flow the implementer finds failing for an iOS-only UI reason (sheet presentation, date pickers) gets the same `when` branch and is listed in the PR; a flow may **not** be skipped on iOS without saying why.
