## Outcome
Switching to the trainer's More tab a second time shows it at once, the same way Attention, Clients and Check-ins already do: the tab stays mounted, and any data it already has is shown immediately. It may refresh quietly in the background. The trainee More tab is already kept by the pane book; only check it, and leave it alone if it already behaves.

## Context
- FitBud Tech's 25 Nov 2026 audit listed this as a small leftover after Z14-3: "the More tab still reloads when you switch to it."
- Z14-3 keeps Attention, Clients and Check-ins mounted once visited (`visited` in `TrainerShell.tsx`). More is still rendered as `{tab === "more" ? <TrainerMoreScreen … /> : null}` (around line 615 on `main` at `ddd48f22`), so it unmounts on every leave and `MoreScreen`'s `useEffect` calls `api.listClients({ limit: 1 })` again on every visit, with `activeCount` starting at `null` ("Coach" with no count).
- **D-W14-39**. Do not change how the other three tabs stay loaded, and do not change review or overlay behaviour.

## Gap list
Written against `main` at `ddd48f22`. Re-check each item on the latest `main` before building; drop what is done and say so in the PR (AGENTS.md).

## Acceptance criteria
- [ ] Once the trainer has opened More, leaving it by the tab bar and coming back does **not** remount `TrainerMoreScreen`. The last client-count line (and the rest of the screen) is visible in the same render, with no empty "Coach" flash and no skeleton. A refresh may run in the background after the same stale window the other trainer tabs use (Z14-3, about 30 s), or on pull-to-refresh; it must not block what is already shown.
- [ ] Attention, Clients and Check-ins still stay mounted exactly as today. A test asserts More is in the same "visited / hidden, not unmounted" set as those tabs.
- [ ] Sign-out still clears whatever More was showing (no other user's count).
- [ ] Offline: if a previous count is on screen, it stays; the existing offline notice still appears when a load fails from the network. No raw error text (D-W14-3).
- [ ] `pnpm lint`, `pnpm typecheck`, `pnpm test` pass.

## Decide-and-note
1. **How More stays mounted (recommended):** put More in the same `visited` set as the other trainer tabs (hidden with the same style when it is not selected). Do not invent a second keep-alive mechanism.
2. **Stale refresh (recommended):** reuse the other tabs' return/stale path if it already fits; otherwise refresh on pull-to-refresh and when More has been hidden longer than that same stale window. Say which.
