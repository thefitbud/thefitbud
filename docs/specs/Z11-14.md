## Outcome
A dual-role user can untick "Remember my choice" and be asked again next launch, is offered the coach-view switch when a link needs the trainer role (frame 61), and can switch role from trainer More, as frame 59 promises.

## Context
- Z10-14 rework (W10 report, Held for FitBud UI: "One W11 task owning `AuthProvider`, the shells, `AppRouter` and More"). Z10-14 (#392) left: "Remember my choice" ticked and not interactive (`RoleSelectScreen.tsx:99-107`, no `AuthProvider` flag); `roleSwitchPrompt` (`resolveRoute.ts:160`) and `SwitchRoleSheet` (`RoleSelectScreen.tsx:127`) built but never called; no "Switch role" row in More although frame 59 says you can switch later in More.
- Build:
  1. A persisted remember flag next to `selectedRole` in `lib/sessionStorage.ts` (web `localStorage`; native uses the same JS storage path the selected role already uses, no new native module). When off, the next launch shows role select (frame 59) instead of restoring the role; the role still applies for the current session. Sign-out clears the flag with the rest of the session (`clearPersistedSession`), so the next sign-in starts with the default (ticked). A stored role not in `permittedRoles` is already dropped by `applyMe` (~l.223-226); keep that.
  2. Wire `roleSwitchPrompt` into the deep-link/notification-link path (`useAppDeepLinks.ts`, `AppRouter.tsx`) **for links that need the trainer role only**: in trainee mode such a link opens `SwitchRoleSheet` (frame 61, coach view); confirming switches role and then opens the link; cancelling stays put. A trainee link in trainer mode keeps today's behaviour (the client-view sheet has no frame) and is listed under "Held for FitBud UI".
  3. A "Switch role" row in trainer More (`MoreScreen.tsx`), shown only when the account has both mobile roles, last in the Settings group, that opens role select (frame 59; its copy already says "You can switch later in More"). It does not open `SwitchRoleSheet` (frame 61 is link-specific). Frame 51 has no such row: decide-and-note, listed as a known difference.
  4. Fold-in (Z10-13 follow-up, same file): a quiet `reloadMe` in `AuthProvider` that refreshes `me` without the loading state, used by the profile Save so it no longer bounces to the first tab. `TrainerProfileScreen.tsx` (~l.159, `await refreshSession()`) changes only to call `reloadMe` instead.
- **Not built:** the client-view switch sheet (no frame; W10 Held answer).
- Roles always come from the server's `permittedRoles`; a stored role the server no longer permits is dropped.
- Runs after Z11-8 (same `AuthProvider.tsx`).
