## Outcome
The optional QA workflow's Playwright job no longer runs `playwright install --with-deps` (which fails while the runners' apt mirrors are unreachable); it runs in the Playwright image as `ci.yml`'s e2e and banned-strings jobs do since Z9b-0.

## Context
- W9b report (Z9b-0 follow-up): `qa.yml` still uses `--with-deps` (~l.1472, the web suite job). Z9b-0 moved `ci.yml` jobs into `mcr.microsoft.com/playwright:v1.64.1-noble` with `options: --ipc=host`; the tag matches the locked `playwright@1.64.1`. FitBud UI, 11 Nov 2026.
- Apply the same `container:` block to every `qa.yml` job that installs Playwright browsers, and change the install step to `playwright install chromium` (no `--with-deps`) or drop it if the image already provides the browser at the locked version — match what `ci.yml` does now.
- Check every other step in those jobs still works inside the container (setup-node, corepack, pnpm cache path, any `gh`, `wrangler` or `curl` use). If a step can't run in the container, stop and report.
- **Never dispatch the workflow** (`workflow_dispatch`) and never run its staging seed jobs: they write to staging with secrets. A run triggered by the PR itself is fine to read, but `web-staging` runs only after `seed-web`, which runs only on `main`, never on `pull_request`: expect the browser job to be **skipped** on the PR. The check rests on actionlint (or a YAML parse) plus a diff against `ci.yml`'s container setup.

## Acceptance criteria
- [ ] No `--with-deps` left in `qa.yml`; jobs that need a browser run in the same image tag as `ci.yml`.
- [ ] `actionlint` (if available) or a YAML parse passes; `ci` green on the PR.
- [ ] PR states the PR-triggered QA run's result (browser job expected skipped) and that the container block matches `ci.yml`.
