## Outcome
Pressing Escape right after closing a drawer no longer adds an extra history entry, the check-ins count opens the inbox on To review, and every Home activity line names the client.

## Context
- Covers master-list (v13) items HB1, HV4, N1a (activity lines; bell already done). Everything the implementer needs from those rows is pasted here.
- HB1: an Escape that lands within ~100 ms of a close runs `closeDrawer()` twice and pushes an extra `/`, so Back needs two presses. Fix: close only when a drawer param is present.
- HV4 (D13): no new view; the card opens `/checkins?tab=to-review`; `tabFromParam` already handles it.
- N1a: the bell already names the client (`apps/trainer-web/src/layout/AppShell.tsx:205-224`); the remaining part is Home activity lines.
- Found while planning: the inbox hard-codes ended clients by first name, which breaks for any real client.
- Design guide for every UI task: `docs/design/README.md` (v3 rules and the frame index), `docs/design/DESIGN-NOTES.md` (palette, type, spacing, components, data and time), `docs/design/DECISIONS-21OCT.md`, and the screen spec in `docs/spec/`. Dates read like "Wed 21 Oct" (never ISO), enums always go through `labelFor` (`packages/core/src/labels.ts`), touch targets are at least 44 pt / 44 px, counts and kcal use tabular numbers.
- Design-review step (W11 Z11-1): after capturing, run `node scripts/qa/visual/diff.mjs --task <ID>` on the captures and attach the generated `docs/qa/<ID>/design-review.md` to the PR.
